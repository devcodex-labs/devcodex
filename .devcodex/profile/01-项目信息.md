## 产品定位

DevCodex 是"AI 开发规范注入器"：

1. **核心产物**：`.github/agents/`、`.github/skills/`、`.github/instructions/` 等规范文件（英文）
2. **安装器**：`index.js` CLI，将规范文件复制到目标项目的 `.github/` 目录
3. **文档站**：`website/`，中文为主，存放设计理念、需求、进度、规范镜像
4. **目标用户**：使用 GitHub Copilot Agent 的开发团队

## 版本策略

| 类型 | 规则 |
|------|------|
| **MAJOR**（x.0.0） | 工作流或架构破坏性变更 |
| **MINOR**（1.x.0） | 新增工作流、新增 Skill、新增指令集 |
| **PATCH**（1.0.x） | Bug 修复、文字修正、工具改进 |

- `plugin.json` 的 `version` 字段必须始终与 `package.json` 保持同步

## 当前开发重点

> ⚠️ 此字段随开发进度手动更新，AI 读取时以此为准判断当前阶段优先级。

| 字段 | 内容 |
|------|------|
| **当前阶段** | v1.0.0 开发中 — P1 阶段 |
| **当前焦点** | Agent 双模式 / 存储规范 / 记忆恢复（三个 P1 需求）|
| **优先级原则** | P1 全部完成后再开始 P2；P0 已完成不再修改 |
| **禁止事项** | 当前阶段不得提前开发 P2 功能模块 |



> **状态：本地开发模式**（npm link 激活）

```
e:\MySelf\devcodex\    ← 源码目录（修改在这里）
        ↓  devcodex update（同步命令）
e:\MySelf\.github\     ← 已安装到 MySelf 工作区
```

### 开发循环

```bash
# 日常开发循环
# 1. 在 e:\MySelf\devcodex\ 修改规范文件
# 2. 同步到工作区
cd e:\MySelf
devcodex update

# 3. 新建 Chat 会话（Ctrl+N）验证最新规范是否生效
devcodex status
```

## 发布流程

```bash
# 1. 更新版本
npm version patch|minor|major

# 2. 同步 plugin.json version 字段

# 3. 发布
npm publish --access restricted
```
