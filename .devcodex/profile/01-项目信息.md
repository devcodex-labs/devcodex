## 产品定位

DevCodex 是"AI 开发规范注入器"：

1. **核心产物**：`.github/agents/`、`.github/skills/`、`.github/instructions/` 等规范文件（中文）
2. **安装器**：`index.js` CLI，将规范文件复制到目标项目的 `.github/` 目录
3. **文档站**：`website/`，中文为主，存放设计理念、需求、进度、规范镜像
4. **目标用户**：使用 GitHub Copilot Agent 的开发团队

## ⚠️ Dev 模式必做规则

> **每次修改以下目录中的任何文件后，必须立即同步到工作区 `.github/`，否则 `@devcodex` Agent 仍使用旧版本。**

| 修改目录 | 说明 |
|---------|------|
| `devcodex/agents/` | Agent 定义变更 |
| `devcodex/skills/` | Skill 能力变更 |
| `devcodex/instructions/` | 全局约束变更 |
| `devcodex/prompts/` | Prompt 模板变更 |

### 同步命令

```bash
# 在工作区根目录（E:\MySelf）执行
cd E:\MySelf
node devcodex/index.js update
# 或（npm link 后）：devcodex update
```

### 验证

```bash
node devcodex/index.js status
# 确认：agents 2, skills 34, instructions 11, prompts 20
```

> ⛔ **同步后必须新开 Chat 会话**（Ctrl+N），Copilot 不会热加载已修改的 Agent/Skill 文件。

### ⚠️ Audit 工作流分批执行说明

`@devcodex` 对 devcodex 项目做全面 audit 时，会读取全部 67 个规范文件（34 Skills + 11 Instructions + 2 Agents + 20 Prompts），总内容量超过 Copilot 平台单次响应 token 限制，导致 **"response got too long"** 错误。

**解决方式**：拆分为多轮 audit，每轮指定维度子集（参见 `skills/audit-execution-guide/SKILL.md` 事件驱动定向审查表）。

```

```
