### N-01 `data/pending-fixes.md` 引用已删除的 `self-fix-auto` Skill（D9 引用准确性）

| 验证 | 结论 |
|------|------|
| 合理性 | `pending-fixes.md` 第 6 行 `> **关联 Skill**: [\`self-fix-auto\`](../skills/self-fix-auto/SKILL.md)` 链接指向不存在的文件。v1.0.0 changelog 明确记录"移除 `fix-incident` 和 `self-fix-auto`（对应 Instruction 已完整覆盖）"，但 `pending-fixes.md` 的引用未同步清理 |
| 可实施性 | 修改链接指向当前实际处理 pending-fix 的规范：`14-self-fix.instructions.md` |
| 收益 | 消除断链；AI 执行 self-fix 工作流读取此文件时不会尝试加载不存在的 Skill |

**验证状态**: ✅已验证（`Test-Path skills/self-fix-auto/SKILL.md` = False；grep 确认唯一引用在 pending-fixes.md:6）
**影响文件**: `data/pending-fixes.md` 第 6 行

**反向质疑三问**：
1. 不修复会导致什么具体功能异常？→ AI 执行 self-fix 时读取 pending-fixes.md 可能尝试加载不存在的 Skill 文件，触发 S03（编造规范）降级路径
2. 是否有意的设计选择？→ 否，changelog 明确标记为"移除"，属于遗漏同步
3. 风险可否接受？→ 不可接受，断链会误导 AI 执行路径

## 💡 低风险问题

### N-04 `precheck-status.prompt.md` 和 `token-setup.prompt.md` 使用未加引号的 `applyTo: **`（D2 frontmatter 规范）

| 验证 | 结论 |
|------|------|
| 合理性 | 所有 11 个 instructions 文件统一使用 `applyTo: "**"`（带引号）。但 `precheck-status.prompt.md` (第 4 行)、`token-setup.prompt.md` (第 4 行)、`cp-checklist.prompt.md` (第 4 行)、`problem-analysis.prompt.md` (第 4 行) 使用 `applyTo: **`（不带引号）。YAML 规范中 `**` 不带引号是合法的，但项目内部不一致 |
| 可实施性 | 将 4 个 prompt 文件的 `applyTo: **` 统一为 `applyTo: "**"` |
| 收益 | frontmatter 格式在项目内部完全一致，消除 YAML 解析器差异风险 |

**验证状态**: ✅已验证（grep 确认 4 个 prompt 文件使用无引号格式，11 个 instructions 全部带引号）
**影响文件**: `prompts/precheck-status.prompt.md`、`prompts/token-setup.prompt.md`、`prompts/cp-checklist.prompt.md`、`prompts/problem-analysis.prompt.md`

### N-05 `README.md` 第 53 行提到"VS Code Copilot Chat"，与 N-03 同类 IDE 限定表述（DA-5 受众适配）

| 验证 | 结论 |
|------|------|
| 合理性 | README.md 第 53 行 `在 VS Code Copilot Chat 中输入 @DevCodex 即可开始`。README 是面向所有用户的首要入口文档，WebStorm/Cursor 用户看到此描述可能误以为 DevCodex 仅支持 VS Code |

| 收益 | README 对受众更准确，不排斥非 VS Code 用户 |

**验证状态**: ✅已验证（README.md 第 53 行确认）
**影响文件**: `README.md` 第 53 行
