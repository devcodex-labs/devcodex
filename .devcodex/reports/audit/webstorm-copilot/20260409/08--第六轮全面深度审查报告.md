## 问题 1 分析：文件路径链接与 AI 自动读取机制

### 结论

| 问题 | 结论 |
|------|------|
| Markdown 链接能否在 Copilot Chat 中"点击跳转"？ | ❌ **不能**。Copilot Chat 不渲染 Markdown 超链接为可点击元素 |
| 调整链接后 AI 会自动读取关联文件吗？ | ⚠️ **不是自动的**。AI 根据 instructions 规则决定读取，链接仅作为 AI 可识别的"路径提示" |
| 能否用 `SKILL.md#section` 只读取某个章节？ | ❌ **不能**。`read_file` 工具读取整个文件（或指定行范围），无法按 anchor 读取章节 |
| 当前 `§节名` 约定是否合理？ | ✅ **合理且已是最优解**。AI 读取全文后，`§` 提示告诉 AI 关注哪个章节 |

### 详细分析

**1. Copilot Agent 的文件读取机制**

```
instructions/ (applyTo: "**")
  └─ 平台自动注入 → AI 接收时已在上下文中（无需手动读取）

skills/ (通过 01-common §Skill 按需读取表路由)
  └─ AI 显式调用 read_file 工具 → 整文件读取 → 内部定位章节

data/ / agents/
  └─ AI 按需显式读取
```

- `instructions/` 文件带 `applyTo: "**"` → **平台级自动注入**，AI 收到消息时已在上下文
- `skills/` 文件 → AI 按 `01-common` §Skill 按需读取表 **显式调用 read_file**，每次读取整个文件
- `#anchor` 在 Markdown 渲染时可跳转（如 GitHub 页面），但 **AI 的 read_file 不支持按 anchor 读取**

**2. `§节名` vs `#anchor` 对比**

| 特性 | `§节名`（当前方案） | `#anchor` 链接 |
|------|:------------------:|:--------------:|
| AI 可理解 | ✅ 自然语言提示 | ✅ 但需额外解析 |
| 浏览器/GitHub 可跳转 | ❌ | ✅ |
| IDE Copilot Chat 可跳转 | ❌ | ❌ |
| 粒度控制（只读章节） | ❌ AI 仍读全文 | ❌ AI 仍读全文 |
| 可读性 | ✅ 直观 | 🟡 需转换中文标题 |

**3. 设计建议**

当前 `§` 约定已是最优解，原因：
- AI 的 Skill 文件均较短（20~215 行），整文件读取开销极低
- `§` 约定比 `#anchor` 更灵活（不依赖 Markdown 标题格式化规则）
- 项目已在 `01-common` §Skill 按需读取表 实现了精确路由，只读 1~3 个 Skill 文件
- 真正的"节省"来自路由层面的控制（禁止全量读取 32 个 Skills），而非文件内章节级控制

**验证状态**: ✅已验证（通过分析 Copilot Agent 工具链 read_file / instructions applyTo 机制确认）
