## 触发条件

满足以下**全部条件**时路由到 resume：

1. 用户说"继续"/"恢复"上次中断的任务，或明确引用上一次会话中未完成的任务
2. 记忆文件中存在状态为 🔄 的会话段落

> ⛔ **chat 不产生中断**：chat 会话不记录 🔄 状态，resume 不接受 chat 类型的原始意图。如果记忆中记录的意图是 chat，应视为新会话而非恢复。

## 工作流

1. **读取记忆** — 调用 `memory` Skill 检索最近 🔄 状态的会话段落
2. **还原上下文** — 提取原始意图、已完成步骤、当前 CP 状态、待续内容
3. **确认任务** — 向用户输出恢复摘要，确认是否继续：
   ```
   📋 恢复任务
   
   **原始意图**：[dev/fix/audit/...]
   **任务描述**：[简述]
   **已完成**：[CP1 ✅ / CP2 ✅ / ...]
   **当前状态**：[中断位置]
   **待续**：[下一步操作]
   
   ❓ 确认继续？
   ```
4. **重路由** — 用户确认后，按原始意图路由到对应 Agent：
   - `dev` → 继续 `@dev` 工作流
   - `fix` → 继续 `@fix` 工作流
   - `audit` → 继续 `@audit` 工作流
   - `analyze` → 继续 `@analyze` 工作流
   - `self-fix` → 继续 `@self-fix` 工作流
   - `other` → 继续 `@plan` 工作流

## 约束

- resume 本身不执行任务，**只负责恢复上下文并重路由**
- 若记忆中有多个 🔄 会话，按时间倒序列出，由用户选择恢复哪个
- 重路由后的执行遵循目标 Agent 的完整约束体系（CP 流程、合规检查等）
