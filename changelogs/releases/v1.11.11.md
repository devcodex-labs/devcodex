# v1.11.11 — S02 用户策略优先与服务清理收口

> 发布日期：2026-06-03

## 变更摘要

- 反转 S02 语义为“用户 / 项目策略优先”：默认允许敏感信息、明文连接信息和硬编码出现在用户要求的代码、脚本、配置、文档、测试或报告中。
- 移除“真实秘密不得进入可提交 / 可传播产物”和“连接配置必须唯一来自 `config.local.json`”的默认阻断口径；只有用户当前指令、项目 Profile/README、仓库策略或用户指定的发布流程明确禁止时，才脱敏、占位或改用 env、`secretRef`、secret manager、`config.local.json`。
- 同步 `technical-design`、API 验证、Profile 模板、dev/fix、CP gate、plan-review、testing/database/document-sync、README、website 与 validate 探针，避免 AI 因安全最佳实践主动加严。
- 新增 C22 `ServiceLifecycleCleanup`：AI 为验证启动 dev server、文档站、本地 API/mock、数据库代理、SSH 隧道、Playwright/Cypress server 或压测 target 后，必须在验证完成、失败或最终回复前主动关闭仅由 AI 本轮启动的服务并核验端口释放。
