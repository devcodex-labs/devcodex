# v1.11.13 — 默认简单实现档位与 Profile Auto 别名

> 发布日期：2026-06-04

## 变更摘要

- 修复 `PF-031 / ISSUE-033`：CP1 需求/问题确认新增 `ImplementationComplexityPreference`，用户未要求复杂化时默认 `simple`，并要求 CP2/CP3 继承，防止简单接口或小功能被过度平台化。
- 修复 `PF-032 / ISSUE-034`：Auto v1.1 支持 Profile `config.json` 的 `extensions.devcodex.autoAliases` 精确别名；本项目 active Profile 已配置 `@rocky` 作为 `@devcodex-auto` 的项目别名。
- Runtime 在 `UserPromptSubmit` 解析并应用目标项目后再判定 execution mode，使 workspace-namespace 项目 overlay 中的 auto alias 能正确生效。
- `validate-profile.js` 新增 `extensions.devcodex.autoAliases` schema 校验，拒绝未带 `@`、保留词、空白、重复或非精确 mention token 的别名。
- README、website、instructions、skills、prompts 与治理探针同步更新，确保 `ImplementationComplexityPreference` 和 Profile auto alias 不发生文档/模板/runtime 漂移。

## Changed

- `requirement.prompt.md` 新增 `§2.3 实现复杂度档位（ImplementationComplexityPreference）`。
- `technical-design.prompt.md` 与 `implementation-plan.prompt.md` 要求继承 CP1 复杂度档位，并把升级复杂度的用户确认、维护成本和非目标纳入方案/计划。
- `dev-plan-review` 增加阻断条件：CP1 默认为 `simple` 时，CP2 不得无确认升级到 `balanced/robust`。
- `load-profile`、`01a-profile-loading`、`01-common`、`cp-gate`、`compliance` 与 `10-dev` 同步 Profile auto alias 入口语义。

## Fixed

- 修复模型在需求阶段缺少“简单优先”明确默认值，导致普通翻译接口等任务容易被设计成复杂、完美化、维护成本高的方案。
- 修复 `@devcodex-auto` 入口不便捷且无法由项目 Profile 配置别名的问题。
- 修复 auto execution mode 判定早于项目 target 应用，导致项目 overlay config 无法影响 auto 授权的问题。
- 修复 ProfileImpactCheck 触发口径未覆盖 `config.json` extensions 的缺口。
