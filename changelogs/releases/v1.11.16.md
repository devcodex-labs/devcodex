# v1.11.16 — 治理 intake 行为闭环、跨项目吸纳守门与发布前收敛

> 发布日期：2026-06-10

## 变更摘要

- 补齐主动记录行为级闭环：Hook runtime 新增 `governanceIntakeCandidate` 候选状态与 Stop / PreCompact 收尾提醒；`test-governance-intake.js` 增加用户建议、用户纠错、`record.none + skipReason`、历史编号 false-positive 和普通 chat direct replay；V39 反查 runtime/test 行为探针。
- 修复治理 intake 合理性偏移：普通“以后要怎么...”问句和“没有回答普通问题”不再误触发治理候选；非 `record.none` 的已分流判定必须同时具备 `规范化意图`、`置信度`、`依据` 与 `目标台账` / 已记录编号。
- 修复全维度审计发现项：Hook bootstrap 改为可验证宿主优先；旧台账编号不能单独关闭当前治理候选；补充 Codex profile-agent mismatch、旧编号 false-positive 与临时目录清理回放；同步 README、active Profile、`1.0.1` requirements、pricing、历史 self-fix 页与 V19/V39/V8 新鲜度探针。
- 收窄 C13 文件拆分口径：500 行上限仅约束新建 DevCodex 规范资产 `.md`（instructions / skills / prompts / templates / 规范源等），业务项目需求、技术方案、报告和正式项目文档不因 C13 被机械压缩或拆分。
- 吸纳跨项目 data 台账中的通用建议：新增 `ExistingDomainContractAudit`、`ConfigOwnershipMatrix`、`ApiDocVerificationSync`、`DataMutationPlan`、`AbsorptionDecision`、`FullV1ScopeGuard` 与 `StartupPhaseTrace` 守门。
- 吸纳复审补齐 `TechnicalRouteComparativeGate`：技术路线、架构优化、性能优化、框架能力设计或高维护成本方案在 CP1 最终需求确认前，按条件记录 `ComparativeResearchGate` 证据范围与采纳 / 不采纳理由。
- 修正 source-root 宿主副本治理口径：V8 不再把源码仓根 ignored 宿主副本当作可刷新部署副本，而是作为 source-root host-copy 残留直接失败；V31 反查 `single active deployment target`。

- 修复治理 intake 防漏逻辑从“漏记”偏向“过度提醒”或“薄证据放行”的双向偏移。
- 修复 `ApiDocVerificationSync`、`StartupPhaseTrace` 已吸纳但 CP2 technical-design 模板缺填写位、V13 缺探针的问题。
