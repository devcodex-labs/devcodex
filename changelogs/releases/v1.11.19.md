# v1.11.19 — 剩余 data 吸纳守门扩展与 v2 MCP-first 路线纠偏

> 发布日期：2026-06-12

## 变更摘要

- 吸纳剩余 `data/*.md` 泛化清单，新增 `ProductRequirementTraceabilityGate`、`LocalExecutionConfigProbe`、`ManualReviewEvidenceDataRetention`、`AdjacentScopeExpansionGuard`、`PackageNameAuthorityGate`、`PerformanceBenchmarkFirstGate`、`PublicModuleDifferentiationGate` 与 `V2MCPFirstPlanningGate`。
- 将上述守门同步到 `instructions.md`、dev/fix/audit/test Skill、CP/报告模板、README、website guide 与活动版本需求页，确保已吸纳规范落到可执行门禁，而不是只停留在建议层。
- 修正 DevCodex v2 文档默认路线为 Intent-Gated Hosted Spec MCP / Codex-only MVP，明确 MongoDB、控制台、多租户自定义工作流和本地规则正文缓存不是一期默认范围。
- 补齐 `profile-bootstrap` 按需触发路由，修正 `18-spec-radar` stale anchor 与 audit `6`/`7` 目标类型漂移。
- 新增 `V62` validate 探针和 `test-spec-governance` targeted probe，覆盖剩余吸纳守门、v2 MCP-first 路线、profile-bootstrap 路由与 audit 目标类型同步链路。

## Fixed

- 修复产品原始需求、用户原文或外部约束在方案/报告中缺少追溯矩阵时，容易被二次转述稀释的问题。
- 修复本机验证前未确认可执行配置、连接配置或本地 overlay 可用性，导致验证计划与实际环境脱节的问题。
- 修复人工复核证据只保留口头结论、缺少截图/日志/外部观察数据归档边界的问题。
- 修复相邻模块范围扩大、npm scope/package 权限、公开模块定位、性能优化基线和 v2 MCP-first 规划缺少统一守门的问题。
- 修复 `profile-bootstrap` 只能被动作为工具描述存在、未进入按需路由判断的问题。
- 修复 `18-spec-radar` 对旧锚点的 stale 引用，以及 audit 目标类型数量在 README/Profile/规范源之间不一致的问题。
