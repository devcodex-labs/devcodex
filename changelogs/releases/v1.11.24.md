# v1.11.24 — 需求输入模板链路与产品完整需求模板收口

> 发布日期：2026-06-26  
> 变更类型：规范治理 / 需求模板 / 发布边界  
> 风险级别：P1  
> 向后兼容：✅ 兼容

## 变更摘要

本版本把“需求方原始输入、产品确认、产品完整 PRD、需求变更、Bug 修复”拆成不同模板入口，避免需求方模板、产品模板与 AI 生成的确认文档混写。产品需求继续作为业务事实源本身，不要求产品另写验收标准、测试用例、数据库字段或接口 Schema；技术验收与验证由技术方案、实施计划和测试方案从已确认事实源派生。

## Added

- 新增 `requirement-overview.prompt.md`，对应纯新需求的 `00-需求概况.md`，面向用户、运营、老板等需求方填写。
- 新增 `requirement-change-overview.prompt.md`，对应 `00-需求变更概况.md`，用于既有需求的变更入口。
- 新增 `bug-overview.prompt.md`，对应 `bugs/<问题>/00-问题概况.md`，用于 Bug / 故障 / 异常入口。
- 新增 `product-requirement.prompt.md`，对应 `01-产品需求.md`，用于公司已有产品角色时由产品直接提供完整 PRD，AI 直接据此进入技术方案。
- 新增产品模板正文纯度探针，阻止把 AI / 研发缺口检查章节放入产品填写模板正文。

## Changed

- 将 `requirement.prompt.md` 收敛为 `01-需求确认.md`：由 AI / 产品根据需求方概况归一化形成，最终需需求方与产品双方确认。
- 将需求方模板字段改为口语化问题，明确允许填写“没有 / 不知道 / 暂无 / 需要产品帮忙整理”。
- 将纯新需求、需求变更、Bug 修复、产品完整 PRD 的入口链路分别写入 README、文档站、CP 清单、output paths、dev/fix/audit/test-router skills。
- 明确产品需求不写验收标准；产品需求本身就是验收事实源，技术实现验收写在 `02-技术方案.md`、`04-实施计划.md` 与测试方案中。
- 强化 Mermaid + 文字步骤图 + 节点解释要求，并把前端页面交互、状态反馈、异常路径、返回/撤销/取消等写入需求链路。
- 同步 runtime CP1 识别、instruction fallback、requirement artifact 检查、validate probes 与 `test-spec-governance`。
- 同步工作区 `.github/`、`.claude/`、`AGENTS.md`、`.agents/` 与 `.codex/` 部署副本。

## Fixed

- 修复产品完整需求模板中混入“AI / 研发缺口检查”章节的问题；缺口、冲突和待补信息改为记录在 CP1 摘要、`02-技术方案.md` 或报告中。
- 修复需求方模板把 Bug 修复、纯新需求和需求变更混在同一概况模板的问题。
- 修复用户不易理解“期望结果 / 当前处理方式 / 已知规则与限制 / 示例 / 反例与附件”等字段的问题。
