# v1.11.3 — 命名空间安全边界与宿主配置保护收口

> 发布日期：2026-05-29

## Highlights

- 命名空间安全边界收口：新增共享 `workspace-layout.cjs` 真相源，统一 Hook / CLI / MCP / fallback-check 的 namespace 解析，并阻断 `project` 参数路径穿越。
- 宿主配置保护增强：`init/update --claude` 改为备份 + 保守合并，保留用户 `permissions.ask/deny`、custom hooks 与 custom MCP servers。
- 发布验证链收敛：新增 `scripts/test-cli-behavior.js`、`validate` 的 `V37` 与独立 `test:audit`，把确定性主链和依赖审计链拆开。

## Changed

- 新增 `host-contract-verification` 与 `source-consumer-sync` 两个支撑型 Skill，并增强 `execution-contract`、`test-router`、报告模板、实施计划/进度与 README / website / Profile / 部署副本消费链。
- 补齐 `Intent Expansion Card`、`ConfirmationRequest`、ECR 执行闭环复审与发布验证证据在规范源、报告模板、validate 探针和发布文档中的同步语义。
- 统一规范治理口径：补齐 `spec-governance` / RecordRouter / SCV、Concept Sync Map、HostContractRoute 与 active-root / report / validate 真相源联动。
- `doctor` 现在区分 env 证据和安装痕迹，在多宿主共存时显式输出 `installed hosts`，不再默认偏置为 Codex。

## Fixed

- 修复 `mcp/profile-server.js` 与 `mcp/memory-server.js` 的 `project` 参数路径穿越，避免越界读写工作区外的 profile / memory 文件。
- 修复 workspace-namespace 下 nested monorepo 命名空间碰撞、Hook 运行态 state 落错命名空间、无会话 sticky project 误继承，以及 `migrate-layout` 对 `packages/*` 旧布局的浅扫描问题。
- 修复 Claude adapter 覆盖用户本地配置的问题，为 `CLAUDE.md`、`.claude/settings.json`、`.mcp.json` 增加备份并改为保守合并。
- 修复容器目录（如 `packages/`）在自身带 marker 时被误识别为项目命名空间的问题，避免 nested monorepo workspace guard 回退到浅模型。

- `npm publish --dry-run`
