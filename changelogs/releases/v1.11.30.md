## 变更摘要

本版本同时收口两条治理执行入口：新增 `audit-user-manual` Skill，将用户侧文档审查从分散规则收口为独立聚合入口；新增 `spec-absorption` Skill，将规范吸纳执行面从 `spec-governance` 中拆出，要求最新可吸纳 / 仍需吸纳 / `.devcodex/*/data` 候选先证明通用规范价值、剔除项目独有残留并绑定 DevCodex 当前消费者。

## 新增能力

- 新增 `audit-user-manual`，作为用户侧文档 review、项目文档审查、菜单导航、sidebar 和信息架构审查的薄封装入口。
- 新增 `UserManualReviewScope` 与 `DocsNavigationReviewMatrix` 输出证据，要求审查先冻结目标文档、受众、真相源、发布边界、页面角色、route、label 与 sidebar group。
- 将 `SidebarPageRoleMaterializationProbe`、`SidebarGroupSemanticModelProbe`、`GeneratedSiteGate` 与 `DocsThemeRuntimeVisualProbeGate` 接入用户侧文档审查聚合路径。
- 新增 `spec-absorption`，作为规范吸纳执行入口，覆盖 `.devcodex/*/data` 候选扫描、通用性证明、消费者证明、项目独有规则剔除、分层决策、消费者同步和验证回写。
- 新增 `CommonNormGeneralizationGate` 与 `AbsorptionCandidateConsumerProofGate`，要求 `ServiceSpecReadGate`、`docs/services/<name>`、单项目 route/model/schema 命名等项目私有规则只作为负向样例或 case evidence，不进入 DevCodex 通用规范。

## Skill 与执行链调整

- `routing`、`dev-docs`、`audit-document`、`audit-readme`、`user-manual-authoring`、`audit-execution-guide`、`document-sync`、`test-router` 与 `report` 已同步 `audit-user-manual` 入口。
- dev/fix/audit 报告模板补充 `audit-user-manual / UserManualReviewScope / DocsNavigationReviewMatrix` 证据字段。
- `routing`、`spec-governance`、`test-router`、`report`、`document-sync`、`source-consumer-sync` 与 technical-design / implementation-plan / report prompts 已同步 `spec-absorption` 执行链。
- README、website、Profile 与 `plugin.json` 同步 Skill 数量为 50，并显式说明用户侧文档 review 聚合入口与规范吸纳执行入口。
- `instructions.md`、`instructions/01-common.instructions.md` 与 `instructions/12-audit.instructions.md` 同步审查路由：用户侧文档 / 文档站 / 项目文档 review 叠加 `audit-user-manual`，README / 主入口文档再叠加 `audit-readme`。

## 兼容性

- 不改变 CLI 命令、Hook 入口、包公开 API 或既有 Skill 的触发语义。
- 新 Skill 是审查聚合入口，复用既有用户文档、通用文档、README、复审清单、文档同步和测试路由能力。
- `spec-absorption` 是规范治理执行入口，不改变 RecordRouter 或 SCV 的既有台账分流语义；`spec-governance` 继续负责治理控制面。
