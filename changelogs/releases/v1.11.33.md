## 变更摘要

本版本把此前分散的高风险修复、Profile 三档契约、审计只读边界和发布阻断修复合并为一个经过三轮零发现复审的正式版本，并新增三项通用治理能力：Profile 真相对账、授权本地安全审查的安全兼容呈现、发布凭据拓扑验证。验证链由 V87 扩展到 V90。

## 新增能力

- `DualLayerRepairCollaborationContract` / `repair-collaboration`：所有 repair task 至少使用 lightweight 双层契约，高风险修复使用 full finding-to-patch、handoff integrity 与 independent re-review；触发与模型名称无关（V87）。
- `ProfileTruthReconciliationGate`：项目级 analyze 使用 targeted，对所有 audit 使用 full/PFresh；`ProfileTruthMatrix` 记录声明、实际来源、漂移状态、结论权威和修订路线。只读工作流只矫正结论，不直接修改 Profile（V88）。
- `AuthorizedLocalSecurityAuditPresentationGate`：授权本地安全审查显式记录授权与防御目标，分离用户可见最小证据和隔离本地探针；安全提示发生时用 `SafetyInterruptionCard` 恢复，不承诺绕过平台控制（V89）。
- `PublisherCredentialTopologyGate`：首次发布或 publisher/repository/package/registry/auth topology 变化时核对发布身份、secret scope/access/inheritance、workflow permission、package ownership 与成功运行证据；不读取或输出 secret value（V90）。

## 修复

- MCP workspace-namespace 路径 containment：新增共享 `mcp/path-guard.js`，memory/profile 工具拒绝把项目参数解析到工作区之外；补 CLI 分发依赖闭包和负向 replay。
- Profile 三档共享契约：新增 `mcp/profile-contract.js`，bootstrap、单项目 validator 与全工作区 validator 共享 `profile-lite / profile-standard / profile-closed-loop` 必需文件与生命周期判定；PF-098 修复普通项目版本被错误对齐到 DevCodex pluginVersion 的问题。
- PF-100 补强 source repo instance identity：同包名的历史/重构仓不再仅因 package identity 被施加当前 pluginVersion；只有显式 `--source-repo-profile` 或 exact current plugin root 才启用源码仓版本对齐，并新增 same-package/different-root 回归样例。
- `AuditMutationBoundaryGate`：audit 只记录 finding、报告、审查状态和交接；源码/规范/配置修复必须进入独立 fix/self-fix/dev 契约。
- 生成站点目录链接闭包：目录型链接显式指向 index，新增 `scripts/check-generated-site-links.js` 与正负向测试；fresh build 152 HTML / 0 missing。
- 官网公开定位统一为面向使用者和集成开发者的官方文档站，维护者指南后置；修正历史任务 stale active 状态。
