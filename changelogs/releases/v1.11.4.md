# v1.11.4 — 治理 Intake 与 Profile 本地 overlay 收口

> 发布日期：2026-05-29

## Highlights

- 治理台账增强：`Improvement Intake` 从 `dev` 模式专属收口为**全模式统一规则**，并把 `process-improvements.md` 明确升格为“优化清单（PI）”当前别名。
- Profile 本地私有配置增强：新增 `config.local.json` 受控 overlay 模型，支持长期连接、env 引用与 `extensions.<namespace>` 扩展位，同时保持 `mode` / `agent` / `pluginVersion` 不可被本地覆盖。
- README / 用户文档治理增强：新增 `readme-authoring` 与 `audit-readme`，把 README 默认主视角收口为用户 / 使用者优先，并建立专项 review 路线。

## Changed

- `instructions.md`、`instructions/01-common.instructions.md`、`skills/spec-governance/SKILL.md`、`skills/intent/SKILL.md` 与 `instructions/18-spec-radar.instructions.md` 统一了 Improvement Intake / RecordRouter 的全模式口径与显式回执要求。
- `README.md`、website 开发指南、`data/templates/process-improvements.md` 和 `changelogs/unreleased.md` 同步到新的 PI / PF / PI+PF / VL / none 分流矩阵。
- `spec-radar` 现在明确区分：PC4 三轴诊断仍是 `dev` 专属，但显式记录意图识别与 Improvement Intake 走 `spec-governance` 的全模式规则。

## Added

- 新增 `readme-authoring` 与 `audit-readme` 两个 README 专项 Skill。
- 新增 `scripts/test-governance-intake.js` 与 `scripts/test-readme-governance.js`。
- `validate.js` 新增 `V39`（全模式治理 Intake）与 `V40`（Profile 本地 overlay）探针。
- `config.local.json` 的 schema、env 引用与受控扩展位说明链已接入 Profile prompt、README、website、MCP profile load 与 `validate-profile`。
