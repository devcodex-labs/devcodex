# v1.15.5

> 发布日期：2026-07-31
> 类型：Patch

## 摘要

本版本发布最新 `main` 分支上的用户 README 与 SkillRoute 修复：README 补齐产品入口、工作区 Skill 与 `@rocky` 自动推进配置说明；npm 包运行时补齐 SkillRoute portfolio；并修复 MCP-only 宿主路径下 `profile_load` / `memory_status` 已成功读取但 `skill_route commit` 仍返回 `CONTEXT_BINDING_PENDING` 的路由阻断。

## 主要变更

- README 面向使用者补强：说明 DevCodex 能解决的上下文、记忆、长任务、五宿主一致性和验证闭环问题；保留 Node.js、安装、更新、卸载、工作区 Skill 和宿主原生 Skill 共存的直接用法。
- README 新增 `@rocky` 自动推进说明：默认别名、退出方式、`.devcodex/workspace/profile/config.json` 配置位置、`extensions.devcodex.autoAliases` 替换/关闭规则，以及 Hook 白名单路径与 instruction fallback 的能力边界。
- npm package runtime 补齐 `skills/portfolio.json`，保证已发布包中的 SkillRoute 能读取内置 Skill portfolio，而不是只在源码仓通过。
- `profile_load` 与 `memory_status` / `memory_session_query` / `memory_summary_query` 的 MCP 返回结果新增受 `ContextReadBindingV1` 约束的来源观测回填；当 Hook PostToolUse 未安装来源 receipt 时，SkillRoute 可从已落盘 plan 与真实 MCP 结果恢复 complete receipt。
- SkillRoute runtime contract digest 覆盖新增来源观测 helper 与 memory MCP adapter，避免桥接代码变更后 capability 声明仍假装新鲜。
- 新增回归测试，覆盖“plan 已落盘、MCP source 已读、hook 未收到 PostToolUse、`skill_route commit` 仍应通过”的场景。
