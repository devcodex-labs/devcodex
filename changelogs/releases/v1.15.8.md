# v1.15.8

> 发布日期：2026-08-03
> 类型：Patch

## 摘要

本版本修复新电脑 / fresh workspace 安装后容易遇到的 Profile 初始化与 MCP 上下文绑定问题：MCP 直接调用 `profile_load` / `memory_status` 时，会根据 `.devcodex/<project>` activeRoot 自动推断 workspace-namespace lifecycle state，不再把已观察证据写到 `__workspace__` 导致 `skill_route commit` 继续 `CONTEXT_BINDING_PENDING`；Profile README 基线缺失时，错误提示和 `devcodex status` 会给出完整的 `profile plan/init` 恢复命令。

## 主要变更

- `recordMcpContextSourceObservations` 从 activeRoot 形态推断 workspace-namespace 项目 hook state，即使 MCP caller 未传或误传 `workspaceNamespace=false`，仍会写入 `.memory/hooks/<project>/lifecycle-state.json`。
- `skill_route` MCP-only 场景新增防复发测试：已通过 MCP source observation 读完 mandatory Profile/memory 后，`commit` 必须成功，不得继续报 `CONTEXT_BINDING_PENDING`。
- `profile_context_plan` 在 active target 缺少 `profile/README.md` 时，返回可执行恢复命令：先 `devcodex init`，再 `devcodex profile plan --tier profile-lite` 与 `devcodex profile init --tier profile-lite`。
- `devcodex status` 的 Profile missing 提示改为完整 plan/init 命令，避免用户误以为全局安装失败或需要猜测下一步。
