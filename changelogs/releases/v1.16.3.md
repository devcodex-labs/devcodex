# v1.16.3

> 发布日期：2026-08-04
> 类型：Patch

## 摘要

本版本修复更新 DevCodex 或宿主运行态不一致后，SkillRoute 可能反复提示 `RUNTIME_CONTRACT_STALE`、持续增加 reconciliation 次数，却没有任何可执行恢复动作的问题。同时收口新电脑、多项目 workspace、Profile 目标、memory 写入绑定和治理台账完整性，避免同类故障从其他入口再次出现。

## 主要变更

- 不可执行的旧 SkillRoute 会保留审计事实后结束旧过程义务，不再生成“必须处理但无动作可执行”的信封；下一条真实用户消息自动建立新的路由身份。
- `noProgressCount` 有界饱和，重复 Stop 不再无限输出同一大段恢复提示；`ROOT_PLAN_BLOCKED`、`TURN_ENVELOPE_READBACK_FAILED`、`PLAN_NOT_COMMITTED` 等状态都有可执行动作或明确终态。
- 用户级宿主运行态按版本与内容隔离部署。更新不会强制终止已经打开的会话；当前会话可继续使用启动时的版本，新会话使用更新后的版本。
- ContextRead 增加明确的进程与运行时身份握手：只兼容已登记的上一版本差异；未知差异、伪造身份和更旧版本会要求新会话刷新，不放宽参数或绑定校验。
- 新增真实滚动升级回归：保持旧版 Profile MCP 进程运行，部署候选版本，再由新版 Hook 消费旧版回执，验证受支持迁移、项目目标保持和未知差异拒绝。
- `devcodex init --profile <target>` 只解析 workspace 中真实且唯一的项目；不存在、重名或仅存在历史运行态时零写入失败。
- memory daily 写入绑定 allocation 返回的 `sessionId + sessionBinding`；无目标、错绑和旧版无 marker 会话不会写错任务。
- 治理台账增加严格 UTF-8、NUL、重复记录 ID 与完整尾部摘要校验，避免损坏文件被当成可信索引继续传播。
- README 补充更新期间已打开会话与新会话的生效边界，用户仍只需一个 npm 更新命令。
