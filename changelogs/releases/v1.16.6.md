# v1.16.6

> 发布日期：2026-08-10
> 类型：Patch

## 摘要

本版本修复 Windows “帮我审批”/workspace 沙箱环境中的三类恢复问题：单个用户级宿主目录不可读时整批 `status/doctor` 中断；ambient Node launcher 在 DevCodex JavaScript 启动前被拒绝却缺少分型；SkillRoute 在审批或连接中断后把完整 `NextActionEnvelopeV1` 显示到聊天界面。

## 主要修复

- `inspectGlobalHostConfiguration()` 对单宿主 `EPERM/EACCES` 投影 `GLOBAL_HOST_TARGET_UNVERIFIED/sandbox-read-denied`，其余宿主继续检查；非权限异常仍抛出。
- `verifyGlobalHostRuntime()` 对不可验证宿主跳过 target、adapter 与 native 探针，避免把“无法观察”误报成合同失败。
- apply/install/mutation 继续使用严格物理 realpath 边界；不可验证路径不采用 lexical fallback，symlink/junction 逃逸仍阻断。
- 新增 `NodeRuntimeReadinessV1`：无 shell 解析 PATH/PATHEXT，报告当前 Node、ambient launcher、Volta/NVM/FNM/asdf/system provider、shim/script/binary 类型与有界 `node --version` 烟测。
- ambient Node 被审批沙箱拒绝时输出 `sandbox-exec-denied`，明确该故障发生在 DevCodex JavaScript 启动前，Hook 无法自行重试；恢复建议为一次性批准 launcher 或使用可信稳定 Node，而不是永久开启 Full access。
- SkillRoute 可见恢复卡只显示协调说明与精确 `nextCall`；无调用时显示 typed status/nextOp/errorCode，重复无变化提示固定为一行。
- 完整 envelope 保留在结构化 `devcodexNextAction`；Codex/Claude Stop、PostToolUse/PreCompact 以及 Copilot/Grok 输出适配不再静默丢失 carrier。
- `REBIND_SEMANTIC_DRIFT` 继续 fail closed，但会原子写入 `SkillRouteRetirementStateV1`；后续 status/Stop 均返回 terminal retirement 与 `nextCall=null`，禁止再次回放已拒绝的 rebind，下一条真实用户消息重新建路由。

## 用户排障

- `devcodex status` 和 `devcodex doctor` 增加紧凑 Node runtime 行，`--json` 提供完整结构化证据。
- README 新增“帮我审批时反复重新连接”说明，区分宿主目录读取拒绝、Node launcher 启动拒绝、SkillRoute pending/BUDGET_BLOCKED 与旧任务未重载新运行态。
- 安装更新后执行 `devcodex global-adapters apply`，完全关闭旧任务并新建任务，才能加载新的用户级 Hook runtime。

## 测试与兼容性

- 单宿主权限拒绝、兄弟宿主继续、非权限异常、mutation fail-closed 与物理路径逃逸均有负向测试。
- Node readiness 覆盖 system/Volta、binary/shim、PATH missing 与 sandbox execution denied。
- Hook 回归覆盖 exact nextCall、无完整 envelope、无 nextCall typed card、duplicate 单行、structured-first 与用户粘贴文本不误判。
- SkillRoute 状态回归覆盖同语义 rebind 成功、语义漂移拒绝并持久退役、status/Stop 无下一调用，以及退役后再次 rebind 不产生新状态。
- production rebind S15 的第二次 ContextRead 保持与第一次相同的语义输入；语义漂移由独立负向测试验证，探针不再把安全拒绝误判为成功条件。
- 变更均为 additive JSON 字段或人类文本降噪；不新增第三方依赖、网络监听、后台服务或自动 mutation replay。
