# v1.17.0

> 发布日期：2026-08-12
> 类型：Minor / Beta host

## 摘要

本版本把 Cursor 接入 DevCodex canonical host：本地 IDE、交互 CLI 与 Headless CLI 通过用户级 Hook、动态 Plugin、现有 MCP 和渐进式 SkillRoute 共用同一不可变 runtime；Cursor Cloud Agent 因官方不加载用户级 Hook，继续保持 Partial / `UNVERIFIED`。同时修复 Windows `agent` 同名命令碰撞，并加固 Codex/Grok S15 候选证据的当前源码绑定。

## 主要新增

- 六宿主统一 target、安装事务、receipt、status/doctor、能力矩阵和测试分母增加 Cursor Beta。
- 用户级 `~/.cursor/hooks.json` 覆盖 workspaceOpen、sessionStart/sessionEnd、beforeSubmitPrompt、Pre/PostTool、failure、afterAgentResponse、preCompact 与有限 Stop follow-up；关键事件按官方合同 fail closed。
- 动态 Cursor Plugin 只暴露 resolver Skill 与 memory/profile stdio MCP，不复制 80+ Skill 正文，也不重复声明生命周期 Hook。
- Plugin MCP 使用 `${workspaceFolder}` 绑定 Cursor 当前项目；业务 workspace 保持零 `.cursor`、零宿主专属入口产物。
- 本地 IDE、交互 CLI、Headless CLI 与 Cloud Agent 分行报告，adapter/configured/native/direct replay 不互相冒充。

## 主要修复与加固

- Windows native verifier 按 PATH/PATHEXT 优先解析 `cursor-agent.cmd` / `.bat`，经 `cmd.exe /d /c` 启动后校验 Cursor 产品身份，再回退到 `agent`；Grok `agent.exe` 不再被误报为 Cursor。
- 非 production Codex/Grok S15 把当前源码安装到一次性宿主 HOME，并要求 source、generation、mode receipt、route envelope 四个 runtime digest 完全一致，拒绝旧全局 runtime 形成的跨版本假阳性。
- SkillRoute catalog stale 增加有界 index drift 诊断，只报告摘要、增删 Skill ID 与变化字段，不泄露正文或本机路径。
- S15 禁止把含旋转 refresh token 的 Grok OAuth 凭据复制到一次性 HOME；只接受专用持久 candidate HOME 或显式 `XAI_API_KEY`，并拒绝 candidate HOME 与真实 HOME 重合。
- Windows 发布验证器按 npm CLI、PATH 原生 `.exe`、installed CLI、受控 `cmd.exe` 顺序解析 npm/npx，不再由 Node 24 直接 spawn `.cmd` 产生 `EINVAL` 假失败。
- 安全审计复用同一 npm invocation resolver，以 `shell:false` 保留原始 exit code 与 JSON 证据，消除 Node 24 `DEP0190` 和参数拼接风险。

## 证据边界

- 官方 Cursor CLI `2026.08.04-aaa8809` 已在隔离 HOME 中通过 `mcp list` 与 `mcp list-tools`，memory/profile 两个 stdio server 均 ready，并分别枚举 10/6 个工具。
- 该只读证据证明 Plugin、`${workspaceFolder}`、MCP server 与工具协商链可用；隔离 Cursor CLI 未登录，因此模型驱动 Hook/Skill 端到端 replay 仍为 `UNVERIFIED`，不会据此宣称完全支持 Cursor。
- Cursor Cloud Agent 不继承本地用户级 Hook readiness，固定保持 Partial / `UNVERIFIED`。

## 发布前验证

- 必须通过 release-risk full DAG、package-release DAG、Profile 全量校验、安全审计、`git diff --check`、候选 tarball 边界与隔离全局安装 smoke。
- 最终候选必须重新生成 Codex/Grok 当前 runtime 的三阶段 S15 PASS，并通过 capability evidence freshness 与无 probe authority 的 production eligibility 检查。
- R4/ECR 经八轮独立遗漏检查收敛后进入 R6；获得明确发布授权后，仍须按候选冻结、远端 CI、tag、publish 与 R7 顺序执行，任何门禁失败均停止后续动作。
