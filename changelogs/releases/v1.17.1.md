# v1.17.1

> 发布日期：2026-08-12
> 类型：Patch / six-host isolation

## 摘要

本版本修复 `global-adapters apply --home <dir>` 的两层作用域逃逸：目标解析仍可接受 ambient 宿主/共享路径覆盖，而 Grok registry convergence 也仍使用进程原始环境。前者可能把隔离事务写向外部宿主目录，后者可能短暂改动真实用户的 Grok plugin identity。v1.17.1 将显式 HOME 固定为 CLI 隔离权威，并把官方子进程与 resolved Grok target 绑定；六宿主真实/隔离负向探针证明 Cursor 接入不会影响其他宿主。

## 修复内容

- 显式 `--home` 在调用全局配置事务前屏蔽六个宿主 HOME、共享 Skill/runtime/fallback 与 VS Code MCP 的 12 个 ambient 路径覆盖键；所有 target 均从指定 HOME 解析。
- `--home=` 或只含空白的目录参数返回 `CLI_GLOBAL_ADAPTERS_BAD_ARGS`，不允许静默回退到真实用户 HOME。
- 未传 `--home` 时仍保留宿主专属环境变量的既有目标解析行为，避免改变正常安装和高级配置语义。
- Grok 官方 CLI 的派生环境显式设置 `GROK_HOME=GlobalHostTargetV1.root`，与文件事务使用同一 target identity。
- 不修改调用方 `process.env`；隔离 HOME 的配置、插件 registry、备份和验证都留在隔离根目录。
- committed Grok target 缺少 `root` 时以 `GLOBAL_ADAPTERS_GROK_TARGET_ROOT_MISSING` 失败关闭，不允许回退到 ambient `~/.grok`。
- 单测覆盖六宿主 root、共享 root、12 个覆盖键、正确派生环境、原环境不变、legacy 路线、Cursor 同事务非干扰，以及 malformed target 不调用官方 sync。
- 根 `package-lock.json` 与 package/plugin 版本重新同步；`validate-versions` 增加 lockfile 根元数据与 `packages[""]` 的防漂移检查。

## 六宿主非回归边界

- Cursor 仍通过 canonical 六宿主 target、Hook、Plugin、MCP、SkillRoute 与 status/doctor 路线交付；本补丁不改变其公共能力合同。
- Copilot、Claude、Codex、Gemini 与 Grok 的 target 路径、受管配置、runtime 和能力上限不得因 Cursor 安装发生变化。
- Cursor 本地 IDE、交互 CLI 与 Headless 继续标记 Beta；Cursor Cloud Agent 与未登录条件下的模型驱动 Hook/Skill replay 继续为 Partial / `UNVERIFIED`，不升级为 Full。
