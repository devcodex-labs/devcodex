# DevCodex v1.17.11

> 发布日期：2026-08-22
> 类型：Patch / 影响范围验证、Codex Hook 韧性与交付体验增强

## 发布摘要

v1.17.11 修复“日常小改动也被推入完整发布验证”的控制面缺陷：验证计划现在显式区分 V0～V3，并由目的、影响边界和类型化消费者关系选择最小充分节点；只有明确授权的发布或全量审计才能进入 V3。版本同时修复 Codex Hook 空锁恢复、事件输出白名单、SkillRoute rebind 证据顺序、真实 CLI 入口选择、复合慢节点 deadline 与 pack 中断恢复。

本版本还汇入 v1.17.10 之后已经落到 `main` 的工作区目标绑定、Memory 产物链接、公开 Skill 分类目录和用户文档任务化增强。

## 影响范围验证（PF-315）

- 新增 `VerificationIntentV1`，把验证等级固定为 V0 静态检查、V1 定向单元/合同、V2 边界集成、V3 完整发布资格。
- `ValidationPlanV2` 通过类型化 runtime、qualification、release consumer 边构建影响图，保留 V1 兼容投影；未知输入失败关闭，不再静默升级成 full。
- `fast` 改为动态影响选择；`profile-deploy` 与 `package-release` 固定为各自 V2 边界，不能吸收旧 full 清单或其他 dirty boundary。
- `BudgetCardV1` 在执行前给出节点数、重节点和预计耗时；非发布重节点需要绑定精确计划摘要，发布 V3 则需要显式 release authority。
- `ValidationEvidenceV2` 绑定 manifest、候选 dirty identity、节点合同/策略和上游 `nodeReceiptDigest`；只复用身份等价的节点证据，V3 永不复用缓存。
- CLI 以 `--intent` 为正式参数，保留 `--purpose` 兼容别名；新增 `test:delivery` 与 `test:boundary`。

## Codex Hook 与证据链修复（PF-321～PF-327）

- 状态锁现在区分空锁、畸形锁、活跃 lease 和可回收 stale lock；并发写入使用有界 backpressure，避免进程终止窗口留下永久阻断。
- Codex Hook stdout 按事件官方字段白名单投影：`PreToolUse` 的 allow/update 与 deny/block 语义保真，无动作输出为 `{}`，跨宿主私有字段不再泄漏。
- S15 强制 generation 0 零正文加载，观察 generation 1 rebind 后的 entry/closeout 顺序；证据同时绑定真实 PATH Codex CLI、runtime、adapter、raw evidence 和 canonical evidence。
- Windows S15 优先解析有效显式覆盖与 PATH 首个 Codex，再使用受控 fallback，避免同机另一安装冒充日常入口。
- `hooks-runtime`、`cli-behavior`、`pack-clean` 等复合节点把父级 deadline 与内部阶段 timeout 分离，合法慢阶段不再被父级提前误杀。
- npm pack 失败、signal 或 timeout 后显式恢复源码 manifest 与内容投影，防止 postpack 未执行污染后续候选。

## v1.17.10 后的交付体验增强

- `HostWorkspaceBindingV1` 与短 TTL `ProjectTargetLeaseV1` 统一宿主工作区、workspace namespace 和 active project 身份，冲突或歧义时立即重判。
- `ArtifactLinkProjectionV1` 为 Memory、提示和续接输出安全生成 canonical containment 内的可点击本地产物链接。
- 86 个 bundled Skill 由 `PublicSkillTaxonomyV1` 精确分类，公开站提供完整目录、过滤和任务入口；Workspace Skill 保持独立。
- 公开文档扩展 Journey / Trust / Reference、工作流选择、教程、宿主设置、CLI、诊断、运行态维护和术语表，旧 URL 保持兼容。

## 兼容性与发布边界

- 不新增 root runtime dependency、后台服务、网络监听、registry 或自定义域名。
- `.playwright-cli/` 继续由 Git/package 路径集合排除；验证不读取、枚举、修改、移动或删除其内容。
- 完整发布资格必须由冻结候选的无缓存 V3、Profile、audit、pack/install、目标提交 CI、tag/GitHub Release、npm registry 与本机更新逐层回读，历史版本证据不可替代。
