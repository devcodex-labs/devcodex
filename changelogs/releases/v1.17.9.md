# DevCodex v1.17.9

> 发布日期：2026-08-17
> 类型：Patch / Grok Hook 启动、所有权与发布链闭环

## 发布摘要

v1.17.9 聚合 v1.17.8 发布后已经核实的失败关闭、事务/CAS、workspace temp V2、Memory 与 Profile current-truth 修复，并关闭 Windows Grok Hook 启动与 lifecycle 所有权问题。

## Grok 修复

- Windows 受管 Hook 命令改为 `cmd.exe /d /s /c call <node> -e ...` 的 canonical transport；同一命令可从 `cmd.exe` 和 Grok 使用的 PowerShell 启动，Node 接收的 argv 保持不变。
- 用户级 `~/.grok/hooks/devcodex.json` 不再声明 DevCodex lifecycle handler，只保留委派说明和合并后仍属于用户的 Hook；六个事件由 `devcodex-workspace` plugin 单独声明。
- verifier 新增 `GrokLifecycleOwnerTopologyV1`，独立报告物理声明数、Grok 精确去重后的有效 handler 数和 mutation owner 数，防止双来源依赖隐式去重形成脆弱拓扑。
- Grok 默认导入 Claude Hook 时，DevCodex Claude stable launcher 必须同时观察到 `GROK_HOOK_EVENT`、`GROK_HOOK_NAME`、`GROK_SESSION_ID`、`GROK_WORKSPACE_ROOT` 才会在读取 receipt 前静默退出；缺任一指纹都不会误跳过原生 Claude 生命周期。

## 兼容性与边界

- 不要求修改 `~/.grok/config.toml` 或关闭整个 Claude 兼容层。
- 用户自有 Grok/Claude Hook 保留；portable Grok 模板继续携带独立 lifecycle 能力。
- Grok 对跨来源完全相同的命令会精确去重，因此旧安装的双声明不被误报为已经发生两次 mutation；修复目标是消除双声明和未来命令漂移风险。
- 不新增第三方依赖、网络服务、端口或常驻进程。

## 验证与发布

发布资格要求 targeted Hook/config/runtime-verifier 回归、六宿主 global install/update、完整测试、coverage、audit、Profile、package/consumer smoke 全部通过；随后按 main CI、annotated tag、Publish、npm/GitHub Release、fresh registry install 和本机更新顺序完成 R5～R7。最终 commit、run、制品摘要及真实 Grok replay 以发布报告和 Profile current truth 为准。
