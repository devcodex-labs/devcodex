# DevCodex v1.19.0

> 发布日期：2026-08-26
> 类型：Minor / 工作流、任务所有权、恢复与验证授权闭环

## 发布摘要

v1.19.0 修复真实工程任务在会话、Hook、工具调用和恢复过程中可能跳过正式需求流程、串入其他任务、绕过产物所有权或重复要求验证确认的问题。DevCodex 现在把真实用户指令、唯一项目、正式任务、可写产物、恢复状态和验证执行绑定到同一组 server-owned 身份与可撤销租约。

本版本同时完成 Lifecycle generation 无界增长的产品化收口：新的 TaskRecoveryStoreV5 按正式任务维护稳定 hot A/B 与 cold resume stub，不再为每次 Hook/工具状态变化创建 UUID 全量 JSON；现有 legacy 文件保持只读且不会被普通维护命令删除。

## 核心变更

### 正式任务与工作流路由

- `ActualInstructionEnvelopeV1` 将用户请求与附件、截图/OCR、引用文档、工具输出、ambient UI 分层，后者只能作为证据，不能覆盖真实指令。
- `WorkspaceSessionRouteIndexV1`、`ProjectTargetLeaseV2` 与 `SessionScopedAuthorityInvariantV1` 绑定 session/project/root/context/route，阻止任务穿插和 terminal 旧绑定复活。
- `FormalTaskAdmissionV1` / `TaskAdmissionTransactionV1` 原子创建任务身份、`00-需求概况.md` 和用户原样 `01-产品需求.md`；ingress idempotency 与 fenced writer 防止重复准入和 mtime 误选任务。
- Simple task 只能使用 server-issued 有界租约；路径、次数或任务范围漂移会升级正式流程并失败关闭。
- Auto 白名单只在正式任务、owner 与 CP 授权全部通过后决定路径策略，不再成为绕过需求流程或直接授予 mutation 权限的入口；非白名单路径在 safety-only 下警告、strict 下拒绝。

### 产物与宿主工具写入

- `MutationFootprintV2 → LayeredArtifactSlotRegistryV2 → ArtifactSlotDecisionV2 → TaskOwnedMutationLeaseV2 → TaskRecoveryStoreV5 prewrite → MutationObservationReceiptV1` 成为正式产物的单一写入决定链。
- Hook、MCP 与宿主工具 mutation 统一进入观察适配层；unknown writer、跨 active-root、错误槽位、重复消费和未观察实际效果均不会被误报为成功。
- `01-产品需求.md` 的产品提供型内容保持用户原始真相，AI 不得静默改写。

### TaskRecoveryStoreV5 与 generation 收敛

- 正式任务使用稳定 hot A/B、cold resume stub 与 terminal 退出缓存；正式任务数无硬上限，默认采用 256/512 MiB soft/hard 与 8 MiB closeout reserve。
- 容量判定、usage ledger 预充和实际写盘共用同一紧凑 JSON 序列，修复“预检可写、格式化后超 256 KiB”的边界分裂。
- 首节点前的 runner/V5 基础设施失败可用有界 `terminalReason.code` 恢复；terminal 任务会解除 session 绑定，防止旧任务占用后续需求。
- Bug 实施期的 CP3 风险/文件阈值计数进入同一 V5 mutation prewrite；即使 PreToolUse、PostToolUse 分进程或宿主中断，第 5 个不同源码/配置文件仍会稳定触发 CP3，且记录被限制为 5 个摘要与路径预览。
- runtime generation GC 继续要求精确摘要与独立授权；普通 status/doctor/maintenance 不删除现有 legacy 或 generation 数据。

### 验证范围、预算与稳定终态

- `VerificationIntentV2`、`ValidationRunIdentityV1`、`VerificationExecutionLeaseV2` 和 `ManagedValidationRunnerV2` 把候选、HEAD、dirty identity、actor、预算、deadline、进程与 exactly-one terminal 绑定。
- plan-only 与 execute 共用 continuation eligibility；预览不写入 authority，purpose/scope/terminal/retry 不合法时返回相同错误，消除“预览可续、执行拒绝”的假绿。
- `PendingBudgetCardBindingV1`、`BudgetConfirmationReceiptV1` 与 `ValidationContinuationAuthorizationV1` 支持 Sticky Auto 的有界续权；续权始终相对 immutable root，同范围最多两次，不能换根清零。
- Auto 新根只允许父运行已终态、无 live lease、当前 committed HEAD 为严格后继且节点/边界/heavy/副作用/预算不扩大；新根保留父 root/terminal 摘要，plan-only 与执行共用同一拒绝路径，底层 evidence store 也禁止带 live lease/runner 换根。
- 普通 changed edit 不再静默升级 V3/full；只有用户明确发布授权或受信 CI/release 角色绑定同一 BudgetCard 时才运行发布级全量验证。
- `PF-342` 摘要稳定化、`PF-343` 稳定终态存储和 actual-candidate evidence gate 同批闭环。

### 宿主与文档边界

- MCP capability/integrity 证据由 server-owned 响应提供，客户端不再自行构造缺字段 schema；HostIdentityV2 区分 CLI、Desktop 与其他宿主证据，禁止跨宿主继承 PASS。
- 宿主专项测试显式固定 fixture 的 host variant 并清除 ambient markers，避免在 Codex、Claude 或普通 shell 中运行同一测试得到不同红绿；生产 Stop enforcement 不因测试环境而改变。
- 根 `README.md`、`public-site/**/*.md` 与 `website/**/*.md` 退出 JavaScript 正文、章节、词句、计数和动态 marker 校验；站点代码、配置、组件、数据与显式 release build 仍按工程范围验证。
- 语法级危险命令分类减少只读搜索和文档文本误拦，真实危险 sink 继续失败关闭。

### Profile 路径可迁移

- 新生成 Profile 的直属 README 声明 `portable-v1`；项目内长期路径统一使用 `<workspace-root>`、`<project-root>`、`<active-root>` 或相对路径，不再把当前盘符或用户目录固化为规范事实。
- `ProfilePathPortabilityGate` 只检查显式目标 Profile 的顶层 Markdown。真实本机外部路径必须同一行标注 machine-local marker；URL 与站点根链接不误报，未声明契约的 legacy Profile 保持兼容。
- D 盘迁移已定向收口 DevCodex Profile：12 处旧工作盘符改为语义根，2 处仍真实位于 E 盘的 DevDocs 路径作为 machine-local 事实保留；其他项目没有进入扫描或修改范围。
- 路径迁移不改写历史报告、receipt 或审计证据，也不删除 legacy generation；可重建派生索引在根变化后按新 active-root 失效重建。

### 正式任务跨物理根续接

- `TaskIdentityV2.projectRootIdentityDigest` 明确收窄为首次准入 provenance；正式任务的可移植身份使用 taskId、project、kind 与 active-root-relative task path，不再把原盘符当成永久任务身份。
- Admission、Lifecycle、Stop 与 MCP takeover 共用 `PortableTaskIdentityBindingDecisionV1`。迁移后必须重新取得当前 active-root containment、ProjectTargetLease、admission 与 fenced owner；旧根的 BudgetCard、validation control、mutation lease 和热态不会恢复实时权限。
- 共享决定先验证完整 `TaskIdentityV2` schema、immutable core 与 `identityDigest`；允许物理根 relocation 不会放宽身份完整性，损坏 identity 在 Lifecycle/Stop 也会失败关闭。
- TaskRecoveryStoreV5 在新物理根使用新的 recoveryKey/session mapping；旧根 A/B 槽与历史 receipt 保留证据且不自动删除。

### 宿主 Skill 精确读取

- Host Skill 隐私防护继续禁止列出用户级 skills 根目录，但允许读取调用方已明确指定的单个 `SKILL.md`，避免 Codex system/plugin Skill 和 DevCodex G_RUNTIME Skill 被误判为目录 inventory。

## 兼容性与数据安全

- Node.js 最低版本、CLI 顶层命令和既有公开 JSON 顶层结构保持兼容；新增字段和命令均为向后兼容扩展。
- 不自动创建功能分支；默认 Git 集成继续采用已确认的同分支直接提交或跨分支 ordered cherry-pick 语义。
- 不迁移、不覆盖、不删除现有 legacy lifecycle 文件；新写入只进入 V5 固定槽。
- DevCodex 仍是跨宿主 AI Coding 工程 Harness：它不提升模型参数、权重、上下文窗口或基础推理上限，而通过上下文、Skill、工作流、工具、记忆、验证与证据链提升真实软件工程中的有效智能表现。

## 发布资格

- 发布前必须通过 source-frozen V3/full、审计、包边界、真实 pack/install、版本与发布元数据校验。
- tag 必须精确指向已通过远端 CI 的 `main` 提交；npm 发布由 `release-pipeline` 使用同一 BudgetCard 形成稳定终态回执，并启用 provenance。
- fresh consumer R7 必须从 registry 安装并核对包身份、CLI、运行时和制品 parity；GitHub Release、npm registry 与 tag 三方版本必须一致。
- 当前控制面继续执行 `RepairPreventionAssessmentGate`、`repair-prevention-assessment`、`ChecklistStateMaterializationGate`、`V94`、`consumer-validation-engineering`、`V95`、`CandidateFreezeGate`、`IsolatedConsumerCwdGate`、`DesignFitnessGate`、`BaseImpactAssessmentV1` 与 `V96`，测试通过本身不替代发布证据。
