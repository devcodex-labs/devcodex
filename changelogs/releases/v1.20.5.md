# v1.20.5 发布候选

> 候选日期：2026-10-18。当前仅准备本地源码候选；正式发行以 npm registry、Git tag 和 GitHub Release 的实际结果为准。

## 用户可见修复

- 恢复与任务所有权：过期且待接管的明确 reopen 可由公开入口准备，再以完整精确 CAS 换代；仅选择完成任务不授予写权。活跃 CLI、未结算操作、身份或终态漂移仍拒绝接管，历史记录保留。
- 需求开发与检查点：CP1/CP2/CP3 模板提供候选分类器所需结构；用户目标使用文档与消费者契约先于技术方案。已确认正文保持版本与摘要，现态由会话、复审、进度和报告投影；结构诊断、语义质量与独立资格分别判断。
- 验收与审阅：scenario-tests 使用真实任务类型；ReviewExecutionPlan 的派生退出要求参与身份校验，防止保留 planId 却弱化独立和轮次要求。公开 reopen 下一调用包含必要 CAS 字段。
- 合法重开后的续接：精确选择任务时，以校验过身份和存储围栏的当前检查点 epoch 状态覆盖历史会话页眉。真正的终态、归档和身份不符仍拒绝自动重开；选择证据不授予写权，也不因无关上下文更新失效。旧式任务保留兼容回退；无明确选择的发现流程仍可能要求稳定 taskId。
- 上下文恢复：失效回执可重试相同规划请求，Hook 登记并消费真实新结果；健康重复、失败调用、会话、目标与 epoch 检查继续保持。
- 验证范围：明确项目原生测试与 DevCodex 受管执行器的适用范围，业务路径不传入 Source runner。业务命令必须留存真实输入、断言、退出码、日志与资源清理证据，不能冒充受管 V3 或发布资格。

## 兼容、升级与恢复

这是现有公开接口的修复补丁，不增加通用迁移、权限绕过或在线数据库恢复能力。安装后通过公开 global-adapters apply 更新受管运行时，并启动新 CLI/MCP 会话；运行中的旧会话按原代际继续，不把文件修改当作旧进程已加载。既有 CP、任务历史和失败记录保留，实际续接仍核对当前 Owner 与来源。

数据库、HTTP、文档和优化样例是隔离工作流验证夹具，不作为生产业务修改发布。Linux 文件独占瞬间探针和维护窗口仅用于该受控夹具，不代表任意在线库可安全复制恢复。

## 验证与发行边界

组件检查、真实 Codex CLI 工作流、最终独立审阅与受管 release/full 资格分别留证。历史版本或不同提交的测试不自动继承为本候选通过；最终依据精确提交、制品身份、命令退出码和对应报告。

当前不声称所有宿主、Node 兼容矩阵、远端 CI、发布凭据拓扑或正式发行已通过。push、tag、publish、deploy 不在本地候选准备动作内。发布失败后按既有 exact-artifact、published-receipt 与 finalize-only 流程恢复，不重复发布。
