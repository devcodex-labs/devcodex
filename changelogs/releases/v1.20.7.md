# v1.20.7

> 候选日期：2026-10-20。正式发行状态以 npm registry、Git tag 和 GitHub Release 的实际结果为准。

## 用户可见变化

- 字段语义：在既有 API 与开发体验规范中补充字段路径、缺省、null、空值、0、false、默认来源及组合语义，减少接口和配置解释的歧义。
- 逐条件证据：候选审查可消费 `ConditionEvidenceMatrixV1`，检查缺行、重复、非法状态，以及缺少证据或运行身份的通过声明。设计覆盖、脚本结果、真实 Agent 行为、集成调用和宿主行为分别记录；结构合格不能代替实际验证。
- 问题归因与确认：Gap 分析先区分规则发现、触发、加载、专业判断及工具环境，再决定修复位置；CP 确认先检查既有决定是否已覆盖当前范围。

## 修复

- 正式任务入口：仅在当前 lease、session、context 与信封身份一致时恢复被压缩的服务端输入；错误身份不能借旧快照准入。
- CP 模板资格：格式正确的 `rejected` 资格回执不再被当成合格候选。失格候选在写入 CP、检查点或 Auto 状态前拒收；错槽错误返回当前阶段的规范产物名称和模板引用，帮助调用方修正路径。合格路径和公开输入契约保持。
- 任务恢复：保留有界的 pending ingress 和在途操作；源码状态维护通过既有 Owner/CAS 和精确文件快照接受当前状态，不重放未知源码写入。
- 验证消费者：同步隔离 HOME、宿主配置、兼容投影和真实 Codex 探针的测试夹具与影响路由，保留原失败证据。
- Windows Grok 安装：向官方 CLI 传入本地插件源路径时统一使用 `/`，避免反斜杠参与插件目录命名，导致长路径下 Skill 和 Hook 漏载。文件目标校验与已保存配置保持原有规则；同目录原生复现已验证路径转换的效果。
- 真实宿主验证归因：隔离 HOME 中的 Hook 锁目录创建、旧 Codex 临时命令别名清理归入运行态变化，避免覆盖宿主拒绝的实际原因；任意文件、别名创建、符号链接和跨目录路径继续拒收。安装态 S15 证据保存在夹具外，失败清理后仍可审阅。
- 生命周期验证工具：支持明确绑定为仅H2/H3的任务验收范围，H1未运行时保持UNVERIFIED；完整范围仍要求原阶段顺序，任务范围不允许申请H1，也不能跳过H2直接接受H3。
- Windows原生验证：隔离配置只沿用已观察到的Windows沙箱后端，不复制全局full-access或审批策略，避免遗漏后端时CLI将workspace-write静默呈现为只读。测试仍使用原定隔离目录和写入边界。
- Codex 项目配置保留：宿主可能把项目 trust 表写入 DevCodex 管理块末尾。重新应用适配器时将这些项目表移到管理块外，卸载时保留；MCP 权威内容篡改、重复项目身份及未知受管表仍拒收，避免运行真实宿主后误报配置冲突或删除项目设置。

## 升级与兼容

没有新增第三方依赖或公开 MCP 参数。升级后通过已安装 CLI 更新工作区运行内容并检查用户级宿主适配器；新 CLI/MCP 进程加载新代际，已运行连接的状态单独核实。

## 验证边界

此前 TaskLifecycle 功能的 19 项真实 Agent 验证只覆盖该功能候选。本版本另行执行源码回归、发布资格、同一 tarball 的隔离安装与 CLI 检查、真实 Codex 宿主探针及本机升级回读。未执行或受到宿主限制的项目保持 UNVERIFIED，不能用脚本通过代替。

发行使用 tag 资格阶段生成的唯一 tarball，经核验后执行已获用户授权的发布与本机升级；版本说明本身不构成发布或安装成功证据。
