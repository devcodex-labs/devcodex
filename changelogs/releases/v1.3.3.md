# DevCodex v1.3.3 — 自我审视机制（Meta-Audit）

> 发布日期：2026-04-13 · 版本类型：MINOR（新增审查元机制）

## 核心变更

### 自我审视机制（Meta-Audit）

**背景**：每次多轮审查即使声明收敛，下一次审查仍能发现新问题。根因是审查机制只检查内容，不分析"上一轮为何漏掉"。引入自我审视机制，让审查系统在发现持续遗漏时自我改进。

**触发条件**：R2 及以后轮次发现新问题时必须执行。

### 四轴盲点分析框架（M1~M4）

| 轴 | 盲点类型 | 典型场景 |
|:--:|---------|---------|
| M1 | 范围盲点 | 新文件不在 CRS 初始关键词命中范围 |
| M2 | 缺席盲点 | 问题是字段/条目"缺失"，grep 无法检测不存在的词 |
| M3 | 层次盲点 | 只查了 Skill 层，漏掉 Instruction 层（最高权威）|
| M4 | 分离盲点 | 路径/名称变更后，引用/applyTo 未跟随更新 |

### 设计原理

自我审视本质是在收敛循环中加入**元层（meta-layer）**：

```
R2+ 发现新问题
  → 四轴诊断（确定盲点类型）
  → 记录 gap-registry
  → 下一轮带着已知盲点定向补查
  → 审查系统逐轮变得更聪明
```

而非仅仅问"有没有问题"（这是一阶检查），还问"为什么上次没发现"（这是二阶检查）。
