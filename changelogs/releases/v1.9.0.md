# v1.9.0 变更日志

> **发布日期**: 2026-05-09  
> **版本类型**: MINOR（新增 Workspace Hooks 分发与宿主硬门禁能力，向后兼容）  
> **关联需求**: `website/docs/versions/v1/1.0.0/requirements/p1/host-lifecycle-gates/index.md`  
> **技术方案**: `website/docs/versions/v1/1.0.0/requirements/p1/host-lifecycle-gates/design.md`

## 概述

本版本完成 Workspace Hooks MVP 的正式落地：新增 `hooks/` 分发面与本地运行时入口，补齐 Hook-First / Instruction-Fallback 双模式文档语义，修复真实 VS Code Hook payload 兼容与危险命令误拦截问题，并完成包校验、站点同步和真实 VS Code 宿主闭环验证。

---

## 变更详情

### Added

- `hooks/devcodex.lifecycle.json`
  - 首阶段 Workspace Hooks 配置入口
  - 覆盖 `UserPromptSubmit` / `PreToolUse` / `PostToolUse` / `PreCompact` / `Stop`
- `hooks/_runtime/lifecycle.cjs`
  - 本地 Hook 运行时入口
  - 提供危险命令护栏与 no-op 生命周期回包
- `website/docs/versions/v1/1.0.0/requirements/p1/host-lifecycle-gates/`
  - 新增需求概况、技术方案、实施计划、进度、关键决策文档
- `.gitignore` 忽略规则
  - 新增 `.tmp-hook-editfiles.json` 与 `.tmp-hook-terminal.json`
  - 防止本地 Hook 回放载荷被误提交

### Changed

#### CLI / 分发面
- `index.js`
  - `init/update/status` 识别并分发 `hooks/` 目录
- `package.json`
  - `files` 白名单纳入 `hooks/`
  - 版本号提升到 `1.9.0`
- `plugin.json`
  - 版本号提升到 `1.9.0`
  - `_hooks_todo` 语义明确为“Workspace Hooks 已分发，plugin-native 后置”

#### Hook 运行时
- `hooks/_runtime/lifecycle.cjs`
  - 新增 `getEventName()`，兼容 `hook_event_name` / `hookEventName` / `eventName` / `event` / `phase`
  - 新增 `getToolName()`，兼容 `tool_name` / `toolName`
  - 危险命令检测收敛为命令型工具和命令字段，避免普通编辑内容误拦截

#### 校验链
- `scripts/validate.js`
  - 校验 `hooks/devcodex.lifecycle.json` 与 `hooks/_runtime/lifecycle.cjs` 已进入正式包面
  - 校验 `assets/hooks/` 不再进入发布包
  - 校验 Hook 命令路径为 `node ./.github/hooks/_runtime/lifecycle.cjs`

#### 文档与需求
- `README.md` / `RULES.md`
  - 明确 Hook-First / Instruction-Fallback 双模式
  - 同步 Hooks 作为 `.github/hooks/` 正式分发面
- `instructions/17-compliance.instructions.md`
  - 将预检查约束改写为宿主兼容语义，而非单纯“首行文本”要求
- `website/docs/versions/v1/1.0.0/requirements/index.md`
  - 新增 `host-lifecycle-gates` 入口
- `website/docs/versions/v1/1.0.0/requirements/p1/{precheck,dev-compliance,exec-compliance}/index.md`
  - 补充对 `host-lifecycle-gates` 的交叉引用

### Fixed

- 真实 VS Code Hook 工具调用 payload 使用 `hook_event_name` 时，正式运行时原先无法识别 `PreToolUse` 的问题
- `PreToolUse` 直接扫描整个 `tool_input` 导致普通编辑内容误拦截的问题
- 工作区根 `.github/hooks/` 在验证后仍残留探针日志文件的问题
- `host-lifecycle-gates/progress.md` 中“真实 VS Code Hook 验证待完成”的事实漂移问题

### Removed

- `assets/hooks/lifecycle.cjs`
  - 失活旧 Hook 源文件已从活动实现面与正式包面移除

## 影响评估

- **向后兼容**：保留原有 instructions / skills 软约束路径；Hooks 仅作为宿主支持时的增强硬门禁层
- **宿主模式**：支持 Hooks 的宿主进入 `hook-enforced`；不支持 Hooks 的宿主继续回退到 `instruction-fallback`
- **用户影响**：VS Code 下的生命周期门禁从“依赖模型服从”升级为“宿主 + 规则协作”，一致性更强；其他宿主的现有行为不被破坏
