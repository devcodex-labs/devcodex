## Fixed

- `package.json` 分发面补入 `mcp/`，真实 npm 发布包现在会包含 `mcp/memory-server.js` 与 `mcp/profile-server.js`。
- `mcp/profile-server.js` 的默认 agent 兜底统一为 `claude-code`，不再回落为裸 `claude`。
- `mcp/memory-server.js` 的 `memory_cp_confirm` 支持 `kind=bugs`，MCP 可以直接维护 bug 任务的 `sessions.md`。
- `hooks/_runtime/lifecycle.cjs` 已覆盖 `.devcodex/bugs/`，并收紧跨任务 CP gate 边界，去掉“任一旧任务 CP3 后全局放行”的宽松逻辑。
- `scripts/instruction-fallback-check.js` 现已对齐运行时规则：跳过 `.archived`，并按任务目录 `mtimeMs` 排序判断未完成任务。
- 新增 `scripts/test-instruction-fallback-check.js`，并在 `scripts/validate.js` 中引入 `V7b` fallback smoke test。
- `instructions` / `skills` / `prompts` / `agents` / `README` 同步补入控制面一致性修订：
  - 新增确认后前置轻量复审规则 `C19`
  - 统一 Claude Auto 的宿主说明
  - 统一 `data/*` 运行时台账语义
  - 统一 `## 会话 NN` 标题口径
  - 重写 `requirement-session.prompt.md` 以匹配 hook 读取的 CP 表格式
  - 报告路径示例改为任务级优先、全局兜底

## Impact

- Claude Code / Copilot Hook / instruction-fallback 三条执行链的控制面边界重新对齐，不再出现“一条放行、一条阻断”的宿主分叉。
- MCP 发布链从“源码可用、npm 包缺件”变为“源码与真实发布物一致”。
- `bugs/` 与 `requirements/` 现在在 MCP、runtime、fallback、测试与核心规范口径上达到同等级支持。
