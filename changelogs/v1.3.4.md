# v1.3.4 — 即发即修元循环（2026-04-14）

## 概述

本版本将审查收敛机制从"批量修复后收敛"升级为"即发即修元循环"：每发现一批问题，立即触发 self-fix 修复，修复完成后重新启动新一轮 audit，如此循环直至连续 3 轮零发现方可收敛。

## 核心变更

### 新增：审查元循环（即发即修）

**文件**：`skills/audit-common/SKILL.md`

- 新增独立章节 `§审查元循环（即发即修）`，定义完整元循环流程
- 每轮发现问题 → 同轮自我审视（M1~M4）→ self-fix 修复 → 重启新轮 audit
- audit 只读原则不变，修复动作发生在 self-fix 子工作流
- 新增元循环状态追踪输出格式（每轮末尾输出）

### 变更：审查收敛条件统一

**文件**：`skills/audit-common/SKILL.md`、`instructions/12-audit.instructions.md`

- 原收敛条件：定向审查 N=2，全面体检 N=3（两套标准）
- 新收敛条件：**所有子类型统一为连续 3 轮零发现**（去掉分支差异）
- 收敛计数规则：只有"零发现"轮次累加，发现问题则归零（修复后重启的新轮才计入）

### 变更：分批执行模板

**文件**：`skills/audit-execution-guide/SKILL.md`

- §分批执行模板：每批次后改为即发即修流程
- 说明即发即修的含义（下一批次审查修复后的最新状态）

## 修复动机

本版本源于观察到"批量修复模式"的根本缺陷：
1. 修复本身可能引入新问题，而这些问题只能在用户下次主动触发审查时才能发现
2. 收敛的"连续 N 轮"应该基于修复后的状态，而非修复前的多轮重复检查

即发即修元循环解决了这个问题：每次修复后立即重验，确保收敛时的状态是"当前代码零问题"而非"上一批代码多轮重复检查无新发现"。
