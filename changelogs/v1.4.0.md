# v1.4.0 — 技术方案流程重构（2026-04-14）

## 概述

本版本对 dev 工作流的技术方案编写与验证流程进行系统性重构：plan-review 拆分为两阶段、新增 PR-7 测试策略检查、dev-default 升级为六阶段（含 N6 方案一致性验证）、技术方案模板增加 §0 现状分析和编写指南，同时完成今日全面深度审查的批量修复（记忆改进/CLI 版本显示/规范一致性修复等）。

## 核心变更

### 1. plan-review 两阶段机制（F-01）

**文件**：`skills/dev-plan-review/SKILL.md`、`skills/dev-default/SKILL.md`、`instructions/10-dev.instructions.md`、`prompts/cp-checklist.prompt.md`、`website/docs/specs/workflow-execution-flow.md`

**变更前**：
```text
CP1 → CP2 [用户确认] → plan-review(PR-1~PR-6) → CP3
```

**变更后**：
```text
CP1 → PR-1 内部自检（AI，不等用户）→ CP2 [用户确认] → plan-review(PR-2~PR-7) → CP3
```

- PR-1（需求完整性）前移到 CP2 前作 AI 内部自检，不通过则修正后重检，通过后才呈给用户 CP2 确认
- 避免用户确认了存在需求缺陷的方案后再被推翻
- 新增短路逻辑：PR 检查按编号顺序，任一 🔴 阻断后立即停止，不继续后续检查

### 2. 新增 PR-7 测试策略与风险评估（F-03）

**文件**：`skills/dev-plan-review/SKILL.md`、`instructions/10-dev.instructions.md`

- 🟡 标注级（不阻断 CP3，但须标注 ⚠️ 并建议补充）
- 检查技术方案 §7 测试策略覆盖目标
- 检查 §9 风险至少识别 1 条技术风险且每条有缓解措施
- 同步更新 dev-database / dev-optimization / dev-refactor 中的 PR 引用

### 3. dev-default 六阶段（F-01/F-07）

**文件**：`skills/dev-default/SKILL.md`、`instructions/10-dev.instructions.md`

- 升级为六阶段：N1 需求确认 → N2 技术方案（含 PR-1 自检）→ N3 方案验证 → N4 实施计划 → N5 执行 → **N6 方案一致性验证**
- N6：执行完成后对照 §2 核心设计逐项确认（模块划分/接口设计/数据流），不一致须说明偏离原因

### 4. 技术方案模板全面升级（F-02/F-04/F-05/F-08/F-09）

**文件**：`prompts/technical-design.prompt.md`、`skills/audit-tech-design/SKILL.md`

- 新增 **§0 现状分析**（🔴 必选）：§0.1 当前架构/代码现状 + §0.2 问题定位
- 新增**编写指南**：章节依赖顺序表（10个章节按依赖关系排列，明确必选/条件）
- §8 **实施阶段划分** → **实施约束**（条件）：消除与 CP3 实施计划的职责重叠
- §1.2 关键架构决策表新增"**为何不选备选**"列（🔴 强制填写）
- 各章节增加 🔴/条件 标注
- 对应 `audit-tech-design` TD-1 同步更新（检查 §0 和"为何不选"）

### 5. 记忆机制改进（M-01~M-06）

**文件**：`instructions/15-memory.instructions.md`、`skills/memory/SKILL.md`、`skills/cp-gate/SKILL.md`、`instructions/17-compliance.instructions.md`、`instructions/10-dev.instructions.md`、`instructions/01-common.instructions.md`、`skills/load-profile/SKILL.md`

- M-01：SUMMARY.md 首步读取策略（标注"首步必做"，从 SUMMARY 快速定位再精读日记）
- M-02：CP1 产物清单补充 `<需求>/.memory/sessions.md` 强制创建
- M-03：Profile config.json 新增 `agent` 字段支持（显式标识 agent 类型）
- M-04：跨会话重新加载约束（会话摘要 ≠ Profile 已加载，必须重新读取）
- M-05：增加 resume 超 14 天的两阶段处理（先查 SUMMARY → 再按需精准读取）
- M-06：SUMMARY 格式统一（多任务会话"一行覆盖全部任务，不拆多行"）

### 6. CLI 版本显示（F-09）
