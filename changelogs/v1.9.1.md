# v1.9.1 变更日志

> **发布日期**: 2026-05-10  
> **版本类型**: PATCH（模板链规则收口、Hooks 运行时硬化、发布安全修复，向后兼容）  
> **关联需求**: `website/docs/versions/v1/1.0.1/requirements/p1/template-flow-alignment/index.md`  
> **相关方案**: `website/docs/versions/v1/1.0.0/requirements/p1/host-lifecycle-gates/design.md`

---

## 概述

本版本在 `v1.9.0` 的 Workspace Hooks MVP 基础上继续做两类收口：

1. 收口默认模板链与 CP3 语义边界，明确 requirement / technical design / implementation plan / implementation progress 各自职责，并把进度文档降为条件触发。
2. 强化 Dev 模式 Hooks 运行时，新增 bootstrap 状态机、回归测试与结束事件 payload 探针，同时移除仓库内明文 GitHub Packages token，避免把发布凭据继续写入跟踪文件。

---

## 变更详情

### Added

- `scripts/test-hooks-runtime.js`
  - 新增 Hooks 运行时冒烟测试
  - 覆盖 bootstrap deny、危险命令 deny、closure reminder 假阳性回归与结束事件 payload capture
- `website/docs/versions/v1/1.0.1/requirements/p1/template-flow-alignment/`
  - 新增活动版本下的模板边界与流程收口需求骨架

### Changed

#### 默认模板链
- `prompts/requirement.prompt.md`
  - 需求模板改为以触发方、可观察反馈和最终结果为主视角
- `prompts/technical-design.prompt.md`
  - 技术方案模板强调现状、目标、实现流程、边界处理与验证策略
- `prompts/implementation-plan.prompt.md`
  - 实施计划模板只承接任务拆分、顺序、依赖、验证与回滚
- `prompts/implementation-progress.prompt.md`
  - 实施进度模板明确为条件触发，不再默认启用
- `prompts/cp-checklist.prompt.md` / `prompts/delivery-checklist.prompt.md`
  - CP3 与交付清单新增任务追溯、验证方式和条件产物校验

#### 规则与文档站
- `instructions/02-output-paths.instructions.md`
  - 明确 `05-实施进度.md` 仅在满足条件且存在 `04-实施计划.md` 时创建
- `instructions/10-dev.instructions.md`
  - 明确 CP3 只确认实施计划边界，不重复技术方案论证
- `skills/cp-gate/SKILL.md` / `skills/dev-default/SKILL.md` / `skills/dev-optimization/SKILL.md`
  - 同步 CP3/实施计划边界与进度文档条件触发
- `website/rspress.config.ts`
  - 调整站点版本入口展示与版本页导航同步逻辑

#### Hook 运行时与发布安全
- `hooks/_runtime/lifecycle.cjs`
  - Dev 模式新增 bootstrap 状态机、artifact touch 跟踪与 closure reminder
  - 修复 `PreCompact/Stop` 无可见回复 payload 时的预检查误报
  - 新增默认关闭、一次性的结束事件 payload probe，用于采集真实宿主字段形状
- `scripts/validate.js`
  - 新增 Hooks 运行时回归校验 V7
- `.npmrc`
  - 改为 `${NODE_AUTH_TOKEN}` 环境变量注入，不再跟踪明文 GitHub Packages token
- `README.md`
  - 安装说明改为环境变量认证写法，避免把 PAT 写入文件

### Fixed

- 修复 Dev 模式下未完成 bootstrap 前仍可能继续进入实质工具操作的问题
- 修复 `PreCompact/Stop` 在没有 assistant 可见回复文本时误报“缺少 DEV 预检查块”的问题
- 修复仓库跟踪 `.npmrc` 明文凭据带来的发布安全风险

---

## 影响评估

- **向后兼容**：未新增工作流类型，也未改变现有 CLI 命令入口；模板与规则调整属于既有能力收口。
- **用户影响**：默认 requirement / design / plan / progress 产物边界更清晰，Dev 模式下的宿主硬门禁更稳定。
- **发布影响**：包版本提升到 `1.9.1`；GitHub Packages 认证改为依赖 `NODE_AUTH_TOKEN` 环境变量。
