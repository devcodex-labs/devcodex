# v1.9.11 — Auto v1.1 runtime 收口 + 控制面校验补强

> **发布日期**: 2026-05-22  
> **类型**: PATCH  
> **关联报告**: `.devcodex/bugs/devcodex-auto模式智能性不足/reports/claude-code/20260521/01--auto实施与验证.md`

---

## Fixed

- 将 Auto v1.1 的正式入口收敛为显式 `@devcodex-auto`，不再把 `auto:` / `/auto` / profile `executionMode` 误写成当前已生效能力。
- 在 `hooks/_runtime/lifecycle.cjs` 中新增 `executionMode` 状态与 Auto 白名单门禁：仅对白名单路径自动推进，非白名单默认回确认模式，危险命令仍保持阻断。
- 补齐 `scripts/test-hooks-runtime.js` 的 auto 专属回归用例，覆盖 executionMode 写入、白名单放行、非白名单阻断与危险命令阻断。
- 扩展 `scripts/validate.js` V14，校验 agent / instructions / skills / runtime / test / README 的 auto 语义联动。
- 同步 README 与父级 `.github/.claude` 部署副本，消除“源码已改、部署滞后”的 V8 噪音。
- 继续收紧 bootstrap：`hooks/_runtime/lifecycle.cjs` 现在只接受当前 agent 的 `SUMMARY.md` 与今日/昨日 `tasks/YYYYMMDD.md`，并在 profile 缺少 `agent` 时按宿主环境与已有 memory 目录推断单一 fallback agent，避免错误 agent 或陈旧 tasks 误满足 bootstrap。
- `scripts/test-hooks-runtime.js` 补齐 wrong-agent、stale-task 与 missing-agent fallback 三类回归场景，保证 bootstrap 收口后的关键分支有自动化覆盖。
- `index.js` 的 `profile init` 生成器改为表格模板；`scripts/validate-profile.js` 同步兼容表格与旧列表格式，并新增 `01-项目信息.md` 的当前版本/当前阶段真相源漂移检查，修复“初始化后立刻误报 missing entry”的问题。
- `scripts/validate.js` 的 V10 不再执行自由字符串 `scanCmd`，改为结构化 `grepCount` 探针与受控 legacy 兼容解析；同时新增 V15，对 `.devcodex/.audit-state/*.json` 的状态枚举与 `converged` 门禁进行一致性校验。

## Validation

- `npm run test:all`
- `node scripts/validate.js`
- `npm view @vextjs/devcodex version --registry https://npm.pkg.github.com`（发布前确认当前 registry 为 `1.9.10`，需要 bump 后才能 publish）
- `node scripts/test-hooks-runtime.js`
- 临时目录执行 `node index.js profile init` 后，再执行 `node scripts/validate-profile.js`，确认不再出现 `missing 当前版本/当前阶段 entry`

## Impact

- Auto 模式从“仅 CP 自动通过”提升为可执行的最小 runtime 闭环，但边界仍保持在 hook-enforced + 白名单路径，避免过度承诺。
- 非 auto 模式继续走原 confirm 路径；完整回归已覆盖 validate、hooks runtime 与 pack-clean。
- 后续如果要推进 Auto v1.2/v2，可在现有 executionMode 与 V14 基础上继续扩展，不需要重做本轮收口。
- bootstrap 门禁不再依赖宽泛的 `clients/` 路径命中，profile 缺少 `agent` 的合法 warning 场景也有安全兜底，不会留下运行时旁路。
- profile 初始化器、校验器与 audit-state 校验链现在共享一致的机器可读契约，降低“工具自己打自己”或样本静默漂移的风险。
