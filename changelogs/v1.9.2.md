# v1.9.2 变更日志

> **发布日期**: 2026-05-20
> **类型**: MINOR 升级（新增 Skill / CLI 子命令 / 维度，向后兼容）
> **主题**: 跨客户端审计闭环 + 双平台 Bootstrap 硬门禁

---

## 1. 主要变更概览

本版本针对 v1.9.0 引入 Claude Code 适配后留存的"规范分发面单一审计、Bootstrap 单平台、agent 字段散值"三类问题做收口，并补足"跨会话审计断点恢复"与"Profile 自动初始化"两个长期痛点。

---

## 2. 详细变更

### 2.1 双平台 Bootstrap 硬门禁（H5）

- `hooks/_runtime/lifecycle.cjs`
  - `isBootstrapReadTool` 新增 Claude Code 工具名识别：`Read` / `Glob` / `Grep` / `list_dir` / `file_search` / `grep_search` / `semantic_search`
  - `PreToolUse` Bootstrap 拦截条件移除 `platform === 'copilot'` 限制，对两平台均强制要求"先读 Profile + SUMMARY + 今日 tasks，再执行其他工具"
  - `buildBootstrapDenyOutput` 接受 `platform` 参数（原硬编码 `'copilot'`），输出对应平台话术

### 2.2 agent 字段枚举固定化（H4 / M2 / R7）

- `instructions/15-memory.instructions.md` / `CLAUDE.md` / `skills/memory/SKILL.md` 三处统一为：
  - 固定枚举：`copilot` / `claude-code` / `codex` / `cursor` / `vscode-copilot` / `zed-copilot` / `unknown-agent`
  - ⛔ 禁止使用裸 `claude`（与 Claude API / Claude.ai 区分）
  - `devcodex init --claude` 必须写入 `"agent": "claude-code"`；`devcodex init` (Copilot) 写入 `"agent": "copilot"`

### 2.3 audit 维度扩展 D23~D25（M6）

- `skills/audit-dimensions/SKILL.md` 新增 I 组「跨客户端适配」：
  - D23 Claude Code 适配层
  - D24 客户端支持矩阵
  - D25 记忆/报告 `<agent>` 字段
- `instructions/12-audit.instructions.md` / `skills/audit-execution-guide/SKILL.md` / `skills/audit-common/SKILL.md` / `prompts/report-audit.prompt.md` / `CLAUDE.md` 同步 `D1~D22` → `D1~D25`

### 2.4 README Client Support Matrix（H6）

- README 新增「Client Support Matrix」章节，明示 Copilot / Claude Code / Cursor / Codex 各客户端注入路径、硬门禁能力、记忆/MCP 支持与等级（🟢 Full / 🟡 Beta / 🔴 Unsupported）
- README 修复 `>` 符号 HTML 转义问题

### 2.5 CLAUDE.md SC/RC/T 完整索引（M1）

- 由仅列关键项扩展为完整 SC1~SC14 / RC1~RC4 / T1~T9 表格
- dev.docs 子类型补 `cp-gate` Skill（M3）

### 2.6 跨会话审计状态机（PF-010 / 新增 Skill）

- 新增 `skills/audit-session/SKILL.md` — 定义审计会话生命周期、状态机、`.devcodex/.audit-state/<session-id>.json` 格式
- `instructions/12-audit.instructions.md` 追加：每轮收敛后写入状态文件；resume + 审计意图时优先读取最近状态文件

### 2.7 Profile 自动生成（PF-011 / 新增 Skill + CLI）

- 新增 `skills/profile-bootstrap/SKILL.md` — 定义扫描产出三件套规则
- `index.js` 新增子命令 `devcodex profile init`：从 `package.json` / `CHANGELOG.md` / 顶层目录 / `.eslintrc*` 等扫描生成 Profile 初稿
- `devcodex status` 输出栏新增 `profile: missing / partial / complete`

### 2.8 v2 旧版本归档（M4）

- `devcodex-v2/README.md` 顶部插入 LEGACY (v1.7.0) 声明，引导用户至 `devcodex-v1/`

### 2.9 Hook 命令跨目录自查找（H7，回归修复）

- **问题**：v1.9.0~1.9.1 的 `CLAUDE_SETTINGS_HOOKS` 使用相对路径 `node .claude/hooks/_runtime/lifecycle.cjs`，当 `settings.json` 安装在 workspace 根目录、而 Claude Code 在项目子目录中运行时，相对路径会以 cwd（项目子目录）为基址解析，导致 `Cannot find module ...devcodex-v1\.claude\hooks\_runtime\lifecycle.cjs` 报错
- **修复**：抽出常量 `CLAUDE_HOOK_COMMAND`，使用内联 `node -e` 脚本从 cwd 向上遍历父目录查找 `.claude/hooks/_runtime/lifecycle.cjs`，找到即 require 执行，找不到则静默 `process.exit(0)`（不阻塞 Claude Code）
- **影响范围**：`index.js`（4 处 hook 配置统一引用常量）+ 已部署的 `.claude/settings.json`（用户须执行 `devcodex update --claude` 同步新命令）
- **回归测试**：从子目录 `cd e:/Worker/devcodex-v1 && echo '{...}' | <new-cmd>` 验证可正确定位 workspace 的 lifecycle.cjs 并输出 `{"continue":true}`

## 3. 不兼容变更（Breaking）

无。本版本所有变更均向后兼容：
- agent 枚举：旧目录 `clients/claude/` 不会被自动迁移，用户首次 `devcodex init --claude` 之后会在 `clients/claude-code/` 创建新目录；旧记忆仍可手工读取
- D23~D25 是新增维度，不影响既有 D1~D22 检查

---

## 4. 升级指南

```bash
# 升级 DevCodex
npm install @vextjs/devcodex@1.9.2

# Copilot 项目
npx devcodex update

# Claude Code 项目（v1.9.0+ 已支持）
npx devcodex update --claude
```

如本地存在 `clients/claude/` 旧目录，建议手工改名为 `clients/claude-code/`，或保留双目录直至所有旧记忆迁移完成。
