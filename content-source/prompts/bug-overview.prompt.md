# Bug 问题概况模板

> **路径**: `.devcodex/**/bugs/<问题>/00-问题概况.md`
> **触发**: Bug 报告 / fix 工作流 CP1 前置
> **填写对象**: 问题报告方 / 测试 / 运营 / 客服 / 用户 / 研发协作方

---

## 编写指引

> ⚠️ Bug 是“已承诺 / 已确认 / 合理预期的行为”与“实际行为”不一致。不得把 Bug 当成产品需求，也不得要求报告方补完整 PRD。
> ⚠️ 报告方重点写清：问题现象、重现步骤、期望行为、实际行为、环境版本、账号 / 数据条件、发生频率、影响范围和证据。
> ⚠️ 报告方不填写根因、修复方案、测试用例、数据库字段、接口 Schema 或技术实现。
> ⚠️ AI / 研发必须根据本文件生成 `01-问题确认.md`、问题分析报告或等价 fix CP1 产物；缺失信息只能标为待确认，不能静默补成已确认事实。
> ⚠️ 如果实际是新增能力，请改用 `requirements/<需求>/00-需求概况.md`；如果是修改已确认需求，请改用 `requirements/<需求>/00-需求变更概况.md`。
