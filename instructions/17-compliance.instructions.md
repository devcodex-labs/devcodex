# 合规检查规则（17-compliance）

> 本 Instructions 定义合规检查的触发时机和约束规则。执行能力见 `skills/core/compliance.skill.md`。

## 触发时机（强制）

- **所有工作流节点执行完毕后、回复发送前**必须执行合规检查
- 检查不通过时修正后重检，直至全部通过
- **chat 豁免** — 不执行合规检查

## 执行顺序

```
FC（形式合规）→ SC（实质合规）→ RC（恢复性检查）→ 报告二次验证（V1~V6）→ 任务完成验证（T1~T9）
```

## 强制约束

### FC 不通过 → 立即修正后重检
- FC1：记忆文件字段完整
- FC2：报告文件已写入（chat 豁免）
- FC3：CP 严格按序（dev/fix）
- FC4：文件名 `NN--` 双横杠开头
- FC5：产物路径已输出（回复末尾双行格式）
- FC6：新建 .md ≤ 500 行

### SC 🔴 阻塞性 → 不通过则阻塞回复
- SC2：dev/fix 编码后已运行 diagnostics
- SC3：fix 已执行三步扫描（同类全局+数据联动+grep零残留）
- SC4：关联文件已同步（dev/fix/self-fix）
- SC6：Agent SUMMARY 已更新（全工作流强制）
- SC8：上次待跟进已查阅
- SC9：C08 Token 防护（>15 轮 🔴 防护 → 先持久化记忆）

### 自修复触发（不进入 self-fix 工作流）

| 触发条件 | 处理方式 |
|---------|---------|
| FC/SC 不通过 | 立即修正后重检（内联，不切工作流）|
| 连续 2 次同类偏差 | 升级分析：追加记忆 `⚠️连续违规` + 报告增加「规范偏差分析」章节 |
| 文件路径不符合 `02-output-paths.instructions.md` | 立即停止创建，迁移到正确路径 |

> ⛔ 合规检查失败的修正在当前工作流内联执行，**禁止进入 self-fix 工作流**（防递归）
