# CP 确认关卡检查清单

> **触发**: CP1 / CP2 / CP3 确认点，规则见 `instructions/10-dev.instructions.md` §CP门控

---

## CP1 — 需求确认关卡

**确认前必须满足**：

- [ ] 用户意图已明确（使用 `intent/SKILL.md` 三问法确认）
- [ ] 功能范围已边界清晰（含排除项）
- [ ] 入口类型已判定：纯新需求 / 需求变更 / Bug 问题；未把 Bug 或需求变更误放进纯新需求模板
- [ ] 纯新需求：需求方原始输入已独立保留为 `00-需求概况.md` 或等价原始附件，未混入产品确认稿
- [ ] 产品完整需求：若已有产品角色直接提交需求，已使用 `01-产品需求.md` 作为产品完整业务事实源；产品模板正文只给产品填写完整 PRD，AI / 研发缺口检查记录在 CP1 摘要、`02-技术方案.md` 或报告中，不生成或重写产品需求
- [ ] 需求变更：变更输入已独立保留为 `00-需求变更概况.md`，已锚定原需求基线、变更前后差异、影响范围和目标真相源
- [ ] Bug 问题：报告方输入已独立保留为 `.devcodex/**/bugs/<问题>/00-问题概况.md`，并转入 `01-问题确认.md` 或等价 fix CP1 报告
- [ ] AI 提炼口径、遗漏和冲突已在 `01-需求确认.md` / `01-需求变更确认.md` / `01-问题确认.md` 标出
- [ ] 产品需求确认稿或需求变更确认稿已由产品补充，并完成需求方 + 产品双方确认
- [ ] 产品需求事实源足以派生技术验收（范围、流程、字段描述、样例、异常、待确认问题清楚）
- [ ] 影响范围初步评估完成
- [ ] 需求入口文档已按类型创建（`requirement-overview.prompt.md` / `requirement-change-overview.prompt.md` / `bug-overview.prompt.md`，SimpleTaskFastPath 可 N/A）
- [ ] 需求确认文档已按模板创建（`requirement.prompt.md`）

**等待用户确认：** → 用户回复"确认"/"通过"/"OK" 后进入 CP2

---

## CP2 — 技术方案确认关卡

**确认前必须满足**：

- [ ] PR-1 需求完整性自检已通过（AI 内部完成，不等用户确认）
- [ ] 技术方案只承接双方确认后的 `01-需求确认.md` / 产品直接提供的 `01-产品需求.md` / `01-需求变更确认.md` / `01-问题确认.md`，不直接把 `00-*` 原始输入当实现口径
- [ ] 架构设计合理，模块职责清晰
- [ ] Breaking Changes 已列出并评估
- [ ] 安全性设计已考虑
- [ ] 测试策略明确
- [ ] 技术方案文档已按模板创建（`technical-design.prompt.md`）

**等待用户确认：** → 用户回复"确认"后进入 plan-review（PR-2~PR-7 详细验证）

---

## CP3 — 实施计划确认关卡

**确认前必须满足**：

- [ ] 任务拆分细化到可独立执行
- [ ] 依赖关系标注
- [ ] 任务与需求项 / 流程节点 / 技术验证项可追溯
- [ ] 每个任务的验证方式已明确
- [ ] 高风险步骤有回滚方案
- [ ] 实施计划与 CP2 方案对应
- [ ] 实施计划文档已按模板创建（`implementation-plan.prompt.md`）

**等待用户确认：** → 用户回复"确认"后开始执行

---

## 用户拒绝处理

用户对 CP 提出修改意见时：
1. 记录修改点
2. 修订对应文档
3. 重新展示修订内容
4. 再次请求确认（最多 3 轮修订）
