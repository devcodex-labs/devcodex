# 纯新需求概况模板

> **路径**: `.devcodex/**/requirements/<中文描述>/00-需求概况.md`
> **触发**: 纯新需求提出阶段 / CP1 前置
> **填写对象**: 用户 / 运营 / 老板 / 客户 / 内部使用方 / 其他需求方

---

## 编写指引

> ⚠️ 本模板只给需求方填写，用来保留原始诉求。它不是产品 PRD，也不是技术方案。
> ⚠️ 本模板只适用于**纯新需求**：新增能力、新页面、新流程、新业务规则或新工具入口。不得把 Bug 修复或需求变更塞进本文件。
> ⚠️ 若是 Bug / 异常 / 已承诺行为与实际不一致，请使用 `.devcodex/**/bugs/<问题>/00-问题概况.md`。
> ⚠️ 若是调整、补充或修改已确认需求，请使用 `00-需求变更概况.md`，并锚定原需求基线、变更前后差异和目标真相源。
> ⚠️ 需求方只需要把“想新增或形成什么能力、为什么需要、希望得到什么结果、有哪些例子或附件、哪里还不确定”写清楚。
> ⚠️ 不会写完整句子也可以，用口语、要点、截图、表格、聊天记录、会议纪要或链接都可以；看不懂或暂时没有的信息，直接写“没有 / 不知道 / 暂无 / 需要产品帮忙整理”。
> ⚠️ 每个填写项都要让需求方一眼知道“这项填什么、可以怎么写、什么时候可以不填、不要写什么”。抽象词必须配口语化解释，不能只给“期望结果、当前处理方式、已知规则与限制、示例/反例”等产品术语。
> ⚠️ 需求方不填写验收标准、测试用例、数据库字段、接口 Schema、技术实现、研发排期或详细交互稿。
> ⚠️ 换句话说：不填写数据库字段、接口 Schema，也不需要把业务诉求翻译成技术字段。
> ⚠️ AI / 产品必须以本文件作为原始输入锚点，生成独立的 `01-需求确认.md`；不得把本文件缺失的信息静默补成产品事实源。
> ⚠️ 若需求方已经提供 Word、PRD、会议纪要、截图、表格、原型、聊天记录或链接，本文件记录来源和关键摘要，附件本身仍是原始事实源的一部分。

## §4 你希望系统帮你做到什么

> **这项填什么**：写“如果这个需求做好了，你希望系统、页面、报表、流程或人员看到什么变化”。不用写技术做法。
> **可以这样写**：例如“运营能直接看到每个渠道的权重结果”“客户提交后能收到明确反馈”“老板能按日期导出汇总表”。
> **可以不填的情况**：还没想清楚时写“需要产品帮忙整理”。
> **不要写什么**：不要写数据库字段、接口、代码方案、验收标准或测试用例。

| 我希望系统 / 页面 / 流程做到什么 | 为什么这个结果有用 | 有多重要 |
|---|---|---|
| | | 必须 / 希望有 / 可后续 |
| | | |

## §5 现在你们怎么凑合处理

> **这项填什么**：写现在没有这个能力时，大家怎么绕路处理、人工处理或临时处理。
> **可以这样写**：例如“现在运营手工 Excel 算权重后发群里”“客服截图给研发查”“客户只能电话问结果”。
> **可以不填的情况**：这是全新业务、现在完全没有处理方式时，写“没有现有流程”。
> **不要写什么**：不要写希望研发怎么改代码；这里只描述现在真实怎么做。

| 问题 | 需求方填写 |
|------|------------|
| 现在怎么做 | |
| 麻烦在哪里 | |
| 哪些地方经常出错或被投诉 | |
| 哪些旧流程必须保留 | |

## §6 有哪些必须遵守的业务口径

> **这项填什么**：写已经明确、不能随便改的规则、限制、口径或依赖。
> **可以这样写**：例如“VIP 客户权重不能低于普通客户”“节假日不计算工作日”“总部和门店看到的数据范围不同”。
> **可以不填的情况**：不确定有没有规则时写“暂不确定，需要产品确认”。
> **不要写什么**：不要把猜测写成确定规则；不确定就标出来。

| 必须遵守的业务口径 | 来源或说明 | 是否确定 |
|---|---|---|
| | | 确定 / 不确定 |
| | | |

## §7 给例子和材料

> **这项填什么**：给产品和研发能看懂的真实例子、不能接受的例子、边界情况和材料。
> **可以这样写**：把截图、表格、聊天记录、竞品链接、会议纪要或一条真实业务数据贴进来；没有附件也可以用文字描述。
> **可以不填的情况**：暂时没有材料时写“暂无，后续补充”。
> **不要写什么**：不要只写“按之前一样”“参考旧系统”但不给链接、截图或说明。

| 类型 | 内容 / 链接 | 说明 |
|------|-------------|------|
| 给一个你希望出现的例子 | | 希望系统最后表现成什么样 |
| 给一个你不能接受的例子 | | 哪种结果一定不行 |
| 给一个容易误解或特殊的情况 | | 极端、少见、边界、例外情况 |
| 放相关材料 | | 截图、表格、原型、会议纪要、聊天记录、竞品链接等 |

## §8 还有哪些拿不准

> **这项填什么**：写你自己也不确定、需要产品 / 研发 / 运营继续确认的问题。
> **可以这样写**：例如“是否要支持历史数据补算不确定”“门店负责人能不能编辑还不确定”。
> **可以不填的情况**：没有不确定问题时写“暂无”。
> **不要写什么**：不要为了显得完整把未确认内容写成确定结论。
