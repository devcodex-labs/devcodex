# 意图驱动

## 你在问什么

为什么同样一句话，有时只出分析，有时会改文件？模型先结合当前请求、已有确认和项目事实解释意图，DevCodex 再检查这份决定的来源、目标和工作流约束。

## 心智模型

意图回答你要完成什么、作用在哪个项目、这次需要结论还是修改。文件操作权限由当前宿主和用户配置决定。

项目选择、流程深度、自动推进、语言偏好和 Skill 选择使用同一份绑定当前消息的语义决定。引用示例、否定句、工具输出和确认消息的包装字段不直接触发这些决定。例如确认窗口用英文标注字段、答案用中文，不表示用户要求切换到英文。已有中文任务偏好会保留，用户明确提出新语言要求时再调整。

工作流是边界，不是标签：`analyze` 保持只读，`fix` 和 `dev` 会进入确认后的修改，`chat` 不走项目执行链。

## 示例

「告诉我测试为什么红，不要改」→ `analyze` 或 `audit`。  
「复现并修好这个失败用例」→ `fix`。  
「继续上次那个需求」→ `resume`，沿用原来的工作流。

## 边界

- 含糊请求可能先被收成规划或要求你补范围，不会偷偷改仓库。
- `plan` 是阶段或能力，不是第九个工作流。
- 自动入口 `@devcodex-auto` / `@rocky` 不会扩大删除、发布或越界权限。
