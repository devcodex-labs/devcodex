# 任务续接

## 你在问什么

换了一个会话，还能接着上次做吗？可以，前提是进度已经写在项目文件里，而不是只留在旧对话窗口。

## 心智模型

`resume` 先读文件真相，再回到原来的工作流和阶段。它自己不发明一种新权限：原来是只读，续接后仍是只读；原来要确认才能改文件，续接后还是要确认。

典型入口：`继续<任务名>任务`。

## 示例

昨天在 `fix` 里定位了失败用例但没改完。今天新开会话说「继续支付回调修复任务」，它应先读报告和记忆，而不是从头再分析一遍。

完整故事见 [跨会话续接案例](/examples/resume)。

## 边界

- 没有项目文件就无法可靠续接。
- 续接不会自动 `push`、发版或扩大删除范围。
- 旧会话不会热加载新安装的 DevCodex，请新开宿主会话。
