# 案例：跨会话续接一次未完成的修复

这是脱敏后的合成案例，不包含任何真实工作区路径或客户数据。

## 场景

一名开发者在周五用 `fix` 定位到测试失败：公开站构建后有一条内部链接 404。根因已经写进报告，但当天没有改完。

周一他新开宿主会话，不再粘贴周五的长对话，只说：

```text
继续公开站死链修复任务
```

## 发生了什么

1. `resume` 读取项目里的报告和记忆，而不是空上下文。
2. 工作流仍是 `fix`：会改文件，但只覆盖已确认的链接修复。
3. 他没有重新授权 `push` 或发版，因此续接后也不会发布。
4. 修复后跑了站点构建和链接检查，把命令结果写回报告。

## 你可以照做

先保证任务进度在项目文件里，而不是只在旧聊天窗口。然后新开会话，用 `继续<任务名>任务`。

更多说明见 [任务续接](/concepts/task-resume) 和 [`resume` 工作流](/workflows/resume)。
