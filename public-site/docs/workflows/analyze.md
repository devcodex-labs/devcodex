# `analyze`：只读分析

新的主入口是 [分析、审查与规划](/workflows/read-only)。本页保留 `/workflows/analyze` 深链，并提供 analyze 的只读边界；`analyze.default` 与 `analyze.research` 的选择以分组页和[工作流索引](/reference/workflows)为准。

## 适用 / 不适用

适用：比较方案、解释现状、给建议，明确不改文件。  
不适用：已经决定要改代码或修缺陷（用 [`dev`](/workflows/dev) 或 [`fix`](/workflows/fix)）。

## 是否改文件

否。

## 阶段

解析问题与 active-root → 声明读取范围 → 定向读取和只读诊断 → 区分事实与推断 → 给出结论、限制和下一步。

## 确认边界

没有「改文件」确认。若分析后你要求实施，应重新进入 `dev` 或 `fix`，不能偷偷改。

## 产物

分析报告或对话中的结论，以及没看过的范围。

## 验证

结论能指回读过的文件、页面或命令输出；引用外部事实时说明来源和时间。推断要标明，抽样不能宣称逐文件全读。

## 完成条件

问题已回答，已读/未读范围和限制已写清，没有产生业务文件修改，也没有把建议假装成已落地的结果。

## 示例请求

```text
分析当前公开站信息架构，比较是否要拆六宿主专页。只分析，不修改文件。
```
