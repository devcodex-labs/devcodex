# `analyze`：只读分析

## 适用 / 不适用

适用：比较方案、解释现状、给建议，明确不改文件。  
不适用：已经决定要改代码或修缺陷（用 [`dev`](/workflows/dev) 或 [`fix`](/workflows/fix)）。

## 是否改文件

否。

## 阶段

读范围 → 对照证据 → 给出结论和边界。

## 确认边界

没有「改文件」确认。若分析后你要求实施，应重新进入 `dev` 或 `fix`，不能偷偷改。

## 产物

分析报告或对话中的结论，以及没看过的范围。

## 验证

结论能指回读过的文件或命令输出。推断要标明。

## 完成条件

问题已回答，限制已写清，没有把建议假装成已落地的修改。

## 示例请求

```text
分析当前公开站信息架构，比较是否要拆六宿主专页。只分析，不修改文件。
```
