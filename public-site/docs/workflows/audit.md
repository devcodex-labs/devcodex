# `audit`：基于证据审查

## 适用 / 不适用

适用：对照仓库事实审查代码、文档或方案，指出缺口。  
不适用：审查完立刻动手改（应另开 [`fix`](/workflows/fix) 或 [`dev`](/workflows/dev)）。

## 是否改文件

默认否。除非你另外授权进入修复工作流。

## 阶段

确定审查对象 → 对照证据 → 分类发现 → 写出结论。

## 确认边界

审查本身不应改源码。把 finding 写进需求或缺陷目录可以，但那是记录，不是修复。

## 产物

审查报告、问题清单、未读范围。

## 验证

每条结论能指到路径或命令。不能用「感觉不对」代替证据。

## 完成条件

范围内的问题已分类，无证据的主张已降级，下一步唯一。

## 示例请求

```text
审查当前技术方案是否和仓库里的 9 页测试合同冲突。只审查，不改源码。
```
