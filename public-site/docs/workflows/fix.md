# `fix`：分析并修复

## 适用 / 不适用

适用：有可复现的失败、回归或缺陷，要定位并改掉。  
不适用：还没确定是不是缺陷的调研（用 [`analyze`](/workflows/analyze) 或 [`audit`](/workflows/audit)）。

## 是否改文件

会。先复现和定位，修复方案确认后再改。

## 阶段

复现 → 定位 → 确认修复范围 → 修改 → 回归验证 → 报告。

## 确认边界

修哪些路径、是否顺手重构、是否提交，需要确认。不会因为「看起来相关」就扩大删除或改发布脚本。

## 产物

问题说明、根因、修复、验证证据、报告。

## 验证

至少复现原失败，再跑相关测试。不能只靠「我看了代码」。

## 完成条件

原失败消失，约定的回归没坏，剩余风险写明。

## 示例请求

```text
复现当前失败的文档站点链接检查，定位根因并修复。只改公开站相关文件。
```
