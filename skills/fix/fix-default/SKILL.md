# Fix Default Skill

## 触发条件

用户报告 Bug、功能异常、报错，未匹配 incident/security 子类型时走默认路径。

## 三步扫描（执行前必做）

| 步骤 | 动作 |
|------|------|
| S1 重现 | 确认问题可稳定重现，记录重现步骤 |
| S2 定位 | 代码层面定位根因（文件/函数/行号） |
| S3 影响评估 | 评估受影响范围（功能/接口/用户） |

## CP 流程

- **CP1**：确认问题定性 + 根因分析 + 影响范围
- **CP2**：确认修复方案 + 回归测试策略（不需要 CP3，直接执行）

## 执行阶段

1. 实现修复（最小化变更范围）
2. 编写/更新回归测试
3. api-verification（若涉及接口）
4. impact-review（若影响其他模块）
5. document-sync（若修复涉及文档说明）

## 关键规则

- 修复必须附带回归测试，禁止无测试的 hotfix（emergency 除外）
- 修复范围不得超出问题边界（禁止顺手重构）
- 输出报告：`reports/bugs/` 目录
