# Fix Default Skill

## 触发条件

用户报告 Bug、功能异常、报错，未匹配 incident/security 子类型时走默认路径。

## 问题诊断三步（CP1 前必做）

| 步骤 | 动作 |
|------|------|
| S1 重现 | 确认问题可稳定重现，记录重现步骤 |
| S2 定位 | 代码层面定位根因（文件/函数/行号） |
| S3 影响评估 | 评估受影响范围（功能/接口/用户） |

## CP 流程

- **CP1**：确认问题定性 + 根因分析 + 影响范围
- **CP2**：确认修复方案 + 回归测试策略（不需要 CP3，直接执行）

## 执行阶段

1. 实现修复（最小化变更范围）
2. 编写/更新回归测试
3. **修复三步必做**（SC3 强制，执行后立即扫描）：
   - 同类全局扫描 — 同一模式错误是否存在于其他位置
   - 数据联动扫描 — 上下游数据流是否受影响
   - grep 零残留复核 — 确认无残留引用
4. api-verification（若涉及接口）
5. impact-review（若 PR-5② 跨模块架构依赖变更）
6. document-sync（若修复涉及文档说明）

## 关键规则

- 修复必须附带回归测试，禁止无测试的 hotfix（emergency 除外）
- 修复范围不得超出问题边界（禁止顺手重构）
- 输出报告：`reports/bugs/` 目录
