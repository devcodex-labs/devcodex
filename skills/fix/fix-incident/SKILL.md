# Fix Incident Skill

## 触发条件

生产环境事故：服务不可用、数据异常、安全泄露、核心功能失效。P0（全面中断）或 P1（核心降级）级别。

## 事故级别

| 级别 | 定义 | 响应时效 |
|------|------|---------|
| P0 | 服务完全不可用 / 数据丢失风险 | 立即响应，15 分钟内给出初步方案 |
| P1 | 核心功能降级 / 影响 >10% 用户 | 1 小时内响应 |
| P2 | 非核心功能异常 | 走 fix-default 流程 |

## 简化 CP1/CP2（P0/P1 允许）

P0/P1 事故时，CP1 和 CP2 可**口述简化**：
- CP1：一句话描述问题现象 + 一句话临时止血方案，无需书面文档
- CP2：P0 时修复方案口头确认即可（不等技术方案文件）；P1 保持标准 CP2 流程
- 获得用户口头确认即可继续，不等书面文档完成

## 执行流程

```
止血 → 定位根因 → CP1（简化）→ 修复 → 验证 → 事后复盘
```

| 阶段 | 动作 |
|------|------|
| 止血 | 优先恢复服务（回滚/限流/降级），不等根因分析 |
| 定位 | 分析日志/监控/错误栈，确认根因 |
| 修复 | 最小化变更，不引入新风险 |
| 复盘 | 事后 24h 内输出事故复盘报告 |

## 产出物

- 事故复盘报告：`reports/bugs/<agent>/YYYYMMDD/NN--incident.md`
- 改进 Action Items：纳入下一迭代
