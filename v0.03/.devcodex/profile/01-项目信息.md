## 产品定位

DevCodex 是"AI 开发规范注入器"：

1. **核心产物**：`.github/agents/`、`.github/skills/`、`.github/instructions/` 等 Markdown 规范文件
2. **安装器**：`index.js` CLI，将规范文件复制到目标项目
3. **目标用户**：使用 GitHub Copilot Agent 的开发团队

## 版本策略

| 类型 | 规则 |
|------|------|
| **MAJOR**（x.0.0） | 工作流或架构破坏性变更 |
| **MINOR**（0.x.0） | 新增工作流、新增 Skill、新增指令集 |
| **PATCH**（0.0.x） | Bug 修复、文字修正、工具改进 |

- `CHANGELOG.md` 记录所有版本变更
- `changelogs/vX.Y.Z.md` 存放详细变更日志
- `plugin.json` 中的 `version` 字段必须与 `package.json` 保持同步

## 当前开发模式

> **状态：本地开发模式**（npm link 激活）

```
e:\MySelf\devcodex\    ← 源码目录（修改在这里）
        ↓  devcodex update（同步命令）
e:\MySelf\.github\     ← 已安装到 MySelf 工作区
```

### 开发工作流

```bash
# 第一次初始化（已完成，无需重复）
cd e:\MySelf\devcodex
npm link                    # 将 devcodex 命令链接到全局

# 日常开发循环
# 1. 在 e:\MySelf\devcodex\ 修改规范文件（agents/skills/instructions 等）
# 2. 同步到 MySelf 工作区（必须执行）
cd e:\MySelf
devcodex update             # 同步到 E:\MySelf\.github\（Agent 读取来源）

# 3. 同步到 MySelf 的 .devcodex\（实时验证效果用）
#    将 devcodex 项目的 profile/config 同步到 MySelf 工作区的 .devcodex\
xcopy /E /Y e:\MySelf\devcodex\.devcodex\profile\ e:\MySelf\.devcodex\profile\

# 4. 新建 Chat 会话（Ctrl+N）验证最新规范是否生效
#    无需重启 VS Code，新会话会重新加载 .github\ 下的所有文件

# 验证安装状态
devcodex status
```

### 关键路径对应关系

| 源码位置 | 安装后位置 | 说明 |
|---------|-----------|------|
| `devcodex/agents/` | `.github/agents/` | Agent 定义文件 |
| `devcodex/skills/` | `.github/skills/` | Skill 文件 |
| `devcodex/instructions/` | `.github/instructions/` | 全局指令 |
| `devcodex/prompts/` | `.github/prompts/` | Prompt 模板 |
| `devcodex/hooks/` | `.github/hooks/` | Agent Hooks |

> ⚠️ **每次修改规范文件后都必须执行 `devcodex update`**，否则 VS Code 中的 DevCodex Agent 读取的仍是旧版本。修改后重新开启一个 Chat 会话让 VS Code 重新加载文件。

## 发布流程

```bash
# 1. 更新版本
npm version patch|minor|major

# 2. 更新 plugin.json version 字段（手动同步）

# 3. 运行审计工具
node tools/v5-full-audit.js

# 4. 发布
npm publish --access restricted
```
