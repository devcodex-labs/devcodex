# 需求管理

> AI 在新建需求或更新需求状态时，严格按本页规范执行。

---

## 优先级判断

| 优先级 | 判断标准 | 目录 |
|--------|---------|------|
| **P0** | 项目基础骨架，其他一切的前提（根目录、profile、文档站）| `requirements/p0/` |
| **P1** | 所有功能需求共用的横切规范，必须在 P2 之前定义和实施 | `requirements/p1/` |
| **P2** | 具体功能模块（agents/skills/instructions 等）| `requirements/p2/` |

---

## 新建需求

### P0 / P2（单文件）

在对应目录下创建 `<需求名>.md`，填写以下结构：

```markdown
# 需求：<名称>

**状态**：⬜ 待开发
**优先级**：P0 / P2

## 目标
## 已完成产物（完成后填写）
## 约束
```

### P1（目录 + 5 文件）

```
requirements/p1/<需求名>/
├── index.md       ← 需求概况（立即填写）
├── design.md      ← 技术方案（CP2 后填写）
├── plan.md        ← 实施计划（CP3 后填写）
├── progress.md    ← 实施进度（持续更新）
└── decisions.md   ← 关键决策（随时追加）
```

### 需求概况（index.md）必填结构

```markdown
# <需求名> — 需求概况

> **优先级**：P1 · **状态**：⬜ 待开发

## 需求背景      → 为什么要做
## 需求定义      → 做什么（分条列出）
## 约束条件      → 不能踩的红线（⛔ 开头）
## 流程图        → Mermaid 图（核心流程，必须有）
## 验收标准      → checkbox 列表，定义"完成"的边界
## 关联需求      → 与哪些需求有依赖关系（表格）
## 开发文档      → 链接到 design/plan/progress/decisions（表格）
## 版本变更记录  → 需求演进历史（表格，倒序）
```

---

## 更新需求状态

需求状态变更时，**同步更新以下两处**：

1. `index.md` 页眉：`⬜ 待开发` → `🔄 开发中` → `✅ 已完成`
2. `requirements/index.md` 总览表对应行状态列

---

## 需求变更处理

需求定义发生变更时：

1. 修改 `index.md` 对应内容
2. 在 `index.md` 底部 `版本变更记录` 追加一行
3. 在 `decisions.md` 追加决策记录（如涉及架构决策）
4. 在 `versions/v1/1.0.0/CHANGELOG.md` 追加变更日志行

---

## 更新 sidebar

新增需求文件后，在 `website/rspress.config.ts` 的 `sidebar['/versions/']` 对应分组中加入链接。

> ⛔ AI 每次新建需求文件后，必须同步更新 sidebar，否则页面不可访问。
