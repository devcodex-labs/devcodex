# Agent 执行模式需求

> **优先级**：P1  
> **状态**：⬜ 待开发  
> **关联**：[agents.md](/versions/v1.0.0/requirements/features/agents) · [skills-core.md](/versions/v1.0.0/requirements/features/skills-core)

---

## 背景

当前 DevCodex 仅支持"确认模式"——每个 CP 节点都需要用户明确确认才继续执行。  
用户需要一种"全自动模式"用于快速迭代、CI/CD 场景或熟悉流程后的批量操作。

---

## 需求定义

### 模式一：确认模式（默认）

- CP1 → CP2 → CP3 每个节点等待用户 yes/no
- 合规检查结果展示，等待用户继续
- 适用场景：正式开发、架构变更、生产部署

### 模式二：全自动模式

- 跳过所有 CP 节点确认，AI 自主判断并继续执行
- 安全底线（S01~S06）**不可绕过**，仍强制执行
- C01（删除确认）**不可绕过**，不可逆操作仍需确认
- 合规检查仍执行，失败时自动修正后继续（不暂停等待用户）
- 适用场景：CI/CD 流水线、批量重构、用户已熟悉流程

---

## 切换方式

### 方式 A：会话级指令触发（P1 必须实现）

用户在消息中直接声明：
```
以全自动模式执行：[任务描述]
auto: [任务描述]
/auto [任务描述]
```

### 方式 B：profile 配置（P2 可选）

在 `.devcodex/profile/01-项目概述.md` 中声明：
```yaml
execution-mode: auto   # auto | confirm（默认 confirm）
```

会话级指令优先于 profile 配置（P1 优先级规则）。

---

## 全自动模式约束

| 约束 | 确认模式 | 全自动模式 |
|------|---------|-----------|
| CP1/CP2/CP3 等待确认 | ✅ 必须 | ❌ 跳过 |
| 安全底线 S01~S06 | ✅ 必须 | ✅ 必须（不可跳过）|
| C01 不可逆操作确认 | ✅ 必须 | ✅ 必须（不可跳过）|
| C10 危险命令确认 | ✅ 必须 | ✅ 必须（不可跳过）|
| 合规检查 FC/SC | ✅ 执行 | ✅ 执行（失败自动修正）|
| 记忆写入 | ✅ 自动 | ✅ 自动 |
| 报告写入 | ✅ 自动 | ✅ 自动 |

---

## 失败回退机制

全自动模式下执行失败时：
1. **可恢复错误**（如 lint 失败）：自动重试 ≤2 次，仍失败则停止并标 ⚠️
2. **不可恢复错误**（如安全底线触发）：立即终止，输出错误摘要，**切换回确认模式**等待用户决策
3. **所有失败**均写入记忆文件，以便下次会话 resume
