## 背景

AI 会话是无状态的——每次新会话上下文清空。DevCodex 通过记忆文件（`.devcodex/.memory/`）实现跨会话状态持久化，但当前缺少完整的"新会话启动时如何加载历史记忆"规范。

---

## 需求一：新会话记忆加载

### 触发时机

每次新会话开始时（收到首条用户消息），自动执行以下流程：

```
① 读取当天记忆文件（YYYYMMDD.md）
② 检查是否存在状态为 🔄 的会话段落
③ 如果存在 → 在预检查状态块中提示用户
④ 读取 TASK-INDEX.md 了解当前活跃任务列表
```

### 预检查状态块输出格式

```
---
🔍 预检查（DEV 模式）
- Token 轮次：第 1 轮
- 待跟进事项：⚠️ 上次有待跟进：[简述]       ← 如有
- 未完成任务：⚠️ 存在 🔄 会话：[简述] → 建议先 resume
---
```

### 记忆文件读取顺序

1. 当天文件（优先）：`.devcodex/.memory/clients/<agent>/tasks/YYYYMMDD.md`
2. 需求级记忆（如在需求目录下工作）：`.devcodex/requirements/<name>/.memory/sessions.md`
3. TASK-INDEX.md：`.devcodex/TASK-INDEX.md`

> ⛔ 禁止使用 glob/find 扫描 `.memory/` 目录，必须用目录工具逐层进入

## 需求二：Resume 工作流

### 触发条件

同时满足以下两个条件：
1. 用户说"继续" / "恢复" / "resume" / "上次任务"
2. 记忆中存在状态为 🔄 的会话

> 若用户说"继续"但记忆中无 🔄 会话 → 路由到 `chat` 处理（不触发 resume）

### 执行流程

```
① 读取最近一条 🔄 状态会话
② 解析任务摘要 + 编码检查点 + 最后执行节点
③ 输出恢复摘要（格式见下）
④ 用户确认后 → 重路由到原始工作流（dev/fix/analyze 等）
⑤ 从中断节点继续执行
```

### 恢复摘要格式

```markdown
## 🔄 恢复上次会话

**原始任务**：[任务描述]
**中断位置**：[上次执行到的节点，如 "CP2 已确认，等待 CP3"]
**上次时间**：YYYY-MM-DD HH:mm
**待跟进**：[如有]

---
确认后继续执行，还是重新开始？
```

### 约束

- ⛔ chat 类任务不产生 🔄 状态，resume 不处理 chat 历史
- ⛔ 同一会话内不可 resume（resume 仅跨会话使用）
- 全自动模式（`auto:`）下，如记忆中有 🔄 任务，自动恢复并继续执行（无需用户确认）

## 需求三：TASK-INDEX.md 维护

### 位置

`.devcodex/TASK-INDEX.md`

### 格式

```markdown
# 任务索引

| 任务 ID | 描述 | 工作流 | 状态 | 最后更新 | 记忆文件 |
|---------|------|--------|------|---------|---------|
| T001 | 实现用户登录 | dev > default | 🔄 进行中 | 2026-04-04 | .memory/.../20260404.md#会话01 |
| T002 | 修复登录 500 | fix > default | ✅ 已完成 | 2026-04-03 | .memory/.../20260403.md#会话02 |
```

### 维护规则

- 每次新建任务 → 追加一行，状态 🔄
- 任务完成 → 更新状态为 ✅
- 任务暂停 → 状态保持 🔄，更新最后更新时间
