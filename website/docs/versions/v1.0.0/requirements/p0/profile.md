# 需求：项目信息（.devcodex/profile）

**状态**：✅ 已完成  
**优先级**：P0

---

## 需求背景

DevCodex 在执行每次开发任务时，AI 需要了解当前项目的基本信息、技术栈、代码风格和架构约束，才能生成符合项目规范的代码和文档。`profile/` 目录承担这一角色——它是 AI 读取项目上下文的唯一来源。

---

## Profile 文件用途

| 文件 | AI 读取时机 | 用途 |
|------|------------|------|
| `config.json` | 每次会话开始 | 读取运行模式（`dev` / `prod`），决定预检查行为 |
| `01-项目信息.md` | dev/fix 工作流前置 | 了解项目概述、需求管理规范、版本策略 |
| `02-架构约束.md` | dev/fix 工作流前置 | 了解目录边界、模块职责、命名规则，避免违规操作 |
| `03-代码风格.md` | dev/fix 工作流前置 | 了解 JS/Markdown 规范，生成风格一致的代码 |

> AI 通过 `load-profile` Skill 在每次 dev/fix 工作流开始前读取上述文件。

## 核心规范（已写入 profile）

- 所有需求统一写入 `website/docs/versions/v1.0.0/requirements/`
- 规范文件（agents/skills/instructions）统一用**英文**编写

---

## 后续维护规范

> ⚠️ **开发阶段说明**：v1.0.0 仍在开发中，profile 文件是**动态演进**的，不代表最终态。  
> AI 读取时以**文件当前内容**为准，不应推断或补全未写入的约束。

- `02-架构约束.md` 随开发进度持续更新：
  - 新模块完成后 → 追加对应目录边界约束
  - 发现 AI 违规操作 → 立即追加禁止事项
  - 约束废弃时 → 注明"已废弃：原因"，不直接删除
- `03-代码风格.md` 随实际编码发现问题时更新，不需要 CP 流程
- `config.json` 在生产发布前必须从 `dev` 切换到 `prod`
- profile 文件变更**不需要走 CP 流程**，属于配置类变更，直接修改即可
