## 安全检查流程回顾

```
接收预检查输出（① 已完成）
→ 对用户请求逐项判定 S01~S06
  → 全部通过 → 进入 ③ 写入摘要
  → 操作级违规（S01不可逆/S04 overwrite/S06 危险命令）
    → 阻断该操作 + 给出合规替代 → 继续主流程其余任务
  → 致命违规（S02 硬编码密钥/S03 编造规范）
    → AUDIT_LOG 双写（记忆 + violations.md）→ 终止请求
```

### 触发时机说明

违规审计在主流程中有**两个触发位置**：

| 位置 | 触发方 | 说明 |
|------|--------|------|
| **② 安全检查（主动）** | Agent 预检查后的安全判定 | 请求本身违反 S02/S03 → 立即终止并写审计 |
| **⑨ 执行阶段合规检查（被动）** | compliance Skill 的 FC/SC 检查 | 执行过程中产出了违规内容（如生成的代码含硬编码密钥）→ 事后发现并补写审计 |

> v0.03 中只描述了"触发时写什么"，未明确"在哪个节点触发"。v1.0.0 Stage 文件需在 Agent 中明确这两个触发点。
