## 为什么属于 P0

- 执行流程是整个系统的入口骨架，影响意图识别、安全检查、路由和收尾。
- 这部分虽然重要，但仍是 **v1.0.0 的版本化需求**，不应和永久规范混在一起。
- 后续 v1.x / v2.x 若调整流程，只需更新对应版本目录，不必改动永久规范。

## 当前推荐主链

> 以下主链为 **非 chat 工作流** 的完整路径。  
> chat 分支仍保留“豁免报告，但不豁免记忆与完成前合规检查”的规则。

```text
收到用户消息
→ 预检查
  - 读取 RULES / 安全底线 / 通用规范
  - 识别意图
  - 加载基础 profile 上下文
  - 按意图补充加载完整 profile
  - 确定产物落点
→ 安全检查
→ 写入摘要
→ 检索记忆（轻量读 / 深度读）
→ 前置状态汇总
→ 开发阶段合规检查
→ 路由到工作流（chat / 恢复任务 / 其他工作流）
→ 工作流执行
→ 执行阶段合规检查
→ 输出报告
→ 更新记忆
→ 完成前合规检查
→ 完成
```

> 说明：以上主链中的每个节点都是**必经阶段**。  
> `预检查` 虽然在文本中显示为单个节点，但内部固定包含规则读取、意图识别、profile 加载与产物落点确定，不是可选集合。  
> 预检查之后的状态汇总在独立节点“前置状态汇总”中完成。

## 设计原理

### 1. 先规则，后执行

DevCodex 是会生成报告、记忆与执行产物的体系，不是纯聊天系统。  
因此必须先建立规则基线、项目上下文和产物落点，再进入正式执行阶段。

### 2. 先安全，后摘要与记忆

安全检查是进入正式执行前的闸门。  
只有确认请求未触碰安全底线后，摘要、记忆检索和后续工作流才有意义。

### 3. 先摘要，后记忆

摘要先把当前任务压缩成稳定表示，再去读取记忆，才能更准确地决定：

- 应该匹配哪类历史上下文
- 是轻量读取还是深度恢复
- 是否需要走“恢复任务”路径

### 4. 记忆按意图分级读取

记忆不是一刀切地全部读取：

- 轻量任务可只做 Memory Check
- 复杂任务可做 Memory Load

这样可以兼顾统一骨架与上下文成本控制。

### 5. 开发阶段合规检查是路由前闸门

在 DevCodex 中，只做安全检查还不够。  
进入开发类工作流前，还需要再确认一次“是否已经具备开发执行条件”。

这一层至少应覆盖：

- 项目 / 版本 / profile 是否已明确
- 产物落点是否已明确
- 是否存在应优先恢复的未完成任务
- 当前任务到底是聊天、恢复还是开发执行
- 是否允许进入真实修改，而不只是分析或文档整理

### 6. 执行后与完成前应拆成两类合规检查

在 DevCodex 中，“合规”不只是一类检查，而是至少分成两层：

- **执行阶段合规检查**：检查 workflow 执行过程是否完整、是否遵守执行要求
- **完成前合规检查**：检查报告、记忆、审计和会话状态是否已经闭环

如果不拆开，容易把“过程校验”和“完成确认”混成同一个节点，语义会变得不清楚。

### 7. 主图只表达稳定节点，节点细则后续下沉

后续将根据每个主流程节点，逐步补充对应的 skill / workflow 规范。  
主图负责表达顺序与关系，节点级文档负责表达详细规则。

## 后续承接计划

后续会逐步把每个主节点补齐到对应的 skill 规范或 workflow 规范中：

| 主节点 | 后续承接方向 |
|--------|-------------|
| 预检查 | precheck / output-paths / load-profile / precheck-status |
| 安全检查 | safety / block / violation audit |
| 摘要 | summary |
| 记忆 | memory |
| 开发阶段合规检查 | dev-compliance / pre-route validation |
| 路由 | intent / routing / 恢复任务 |
| 工作流执行 | dev / fix / analyze / audit / self-fix / plan |
| 执行阶段合规检查 | compliance / workflow-validation |
| 完成前合规检查 | completion-compliance / closeout-validation |
| 报告与记忆写入 | report / memory |

## 还需补充的开发检查节点

除新增的“开发阶段合规检查”外，当前还应在以下节点继续补充开发类检查：

| 节点 | 建议补充内容 |
|------|-------------|
| 预检查 | 项目识别、版本识别、profile 完整性 |
| 记忆检索 | 未完成开发任务检测、是否应优先恢复 |

| 完成前合规检查 | 报告、记忆、审计、完成状态闭环 |
