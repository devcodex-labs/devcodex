# 阻断并给出合规替代 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现  
> **归属**：② 安全检查 > 操作级违规分支

---

## 需求背景

当安全检查识别到操作级违规（如不可逆删除、危险命令）时，不能直接终止，也不能直接执行。  
需要一个专门的子流程：阻断该违规操作，分析违规原因，给出等效的合规替代方案，再继续主流程。

---

## 需求定义

该子流程是安全检查操作级违规分支的处理逻辑，包含：

| 步骤 | 说明 |
|------|------|
| 阻断操作 | 拒绝执行违规操作，不产生任何副作用 |
| 说明原因 | 向用户说明为何该操作被阻断（引用具体规则编号）|
| 给出合规替代 | 提供可达到同等目的的合规操作方案 |
| 等待确认或继续 | 不可逆操作需用户确认；可逆操作给出提示后直接执行合规替代 |

### 操作级违规分级

| 违规类型 | 级别 | 处理方式 |
|---------|------|---------|
| 不可逆（删除文件/清空目录）| 🟡 阻断 | 给出替代方案，等待用户明确 yes/no |
| 可逆（重命名/移动）| ℹ️ 轻量提示 | 输出操作计划后直接执行合规替代 |
| 危险命令（无条件 DELETE 等）| 🟡 阻断 | 给出替代方案，等待用户确认 |

---

## 约束条件

- 替代方案必须能达到用户原始目的，不能简单拒绝
- 阻断时必须引用具体规则编号（S01/S06 等）
- 不可逆操作的 yes/no 确认必须是**用户明确输入**，不能自动通过

## 验收标准

- [ ] 操作级违规时不直接执行也不直接终止
- [ ] 阻断信息包含规则编号和原因说明
- [ ] 合规替代方案与用户原始目的等效
- [ ] 不可逆操作必须等待用户明确 yes/no
- [ ] 可逆操作输出提示后直接执行替代
