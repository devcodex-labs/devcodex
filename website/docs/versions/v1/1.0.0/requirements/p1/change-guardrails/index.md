# 变更护栏（提交边界 / 官方文档 / Commit 摘要）— 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

当前 DevCodex 已具备工作流路由、CP 门控、报告与记忆体系，但在“新需求切换”和“外部知识源优先级”两个位置仍存在执行空档：

1. 当工作区存在未提交修改时，Agent 还没有显式识别“用户是否正在切换到一个新需求”，容易把两个任务混在一次会话内继续推进。
2. 当任务涉及框架能力、平台限制、官方 API、版本兼容性或外部工具行为时，现有规范只零散提到“依赖文档”，没有明确要求优先阅读官方文档。
3. 当前提交说明缺少统一的简洁表达约束，容易把会话摘要直接搬进 commit message，导致提交主题过长、可读性差。

上述问题会直接影响任务边界清晰度、提交卫生和方案判断准确性，且与当前 v1.1.0 的规范一致性目标一致，适合纳入独立 P1 需求。

---

## 需求定义

本需求为跨工作流护栏增强，覆盖 `dev`、`fix`、`analyze.research` 及相关通用规则，包含以下三个需求点：

### NR-1：新增“脏工作区 + 新需求切换”提醒

- 当用户当前请求与本会话已执行内容明显不一致，或意图识别为“新增功能/新需求”时，Agent 需先检查当前工作区是否存在未提交变更。
- 判定顺序必须以“意图识别”为主，而不是先看关键词：
  - 如果当前上下文足够支撑意图判断，则按意图判断是否属于新需求切换。
  - 只有在意图无法稳定判断时，才允许退化为关键词、措辞特征或主题漂移等弱信号辅助触发。
- 若存在未提交变更，Agent 必须提醒用户当前变更尚未提交，并明确给出继续方式：
  - 先提交当前变更后再切换新需求；
  - 明确确认继续在同一工作区并行处理；
  - 明确说明本次其实仍属于同一需求的后续。
- 该提醒应作为边界提示，不应默认阻断同一需求的连续迭代，也不应替代安全类强阻断规则。

### NR-2：新增 Commit 摘要简洁化约束

- 当任务进入“准备提交”或“用户要求提交”场景时，Agent 生成的 commit message 主题必须收敛为一句简洁描述。
- 主题应聚焦“本次变更做了什么”，不直接复用大段会话总结，不堆砌背景、风险或验证细节。
- 需要长说明时，应放入补充说明、报告或回复正文，而不是塞进 commit subject。

### NR-3：新增官方文档优先规则

- 当任务涉及以下场景时，Agent 应在继续方案判断或代码实施前优先阅读官方文档或官方参考资料：
  - 框架 / SDK / 平台 API 能力判断
  - 版本兼容性、配置约束、弃用项、Breaking Change
  - VS Code / Copilot / MCP / Node / 浏览器等宿主平台行为
  - 第三方工具参数、命令语义、限制条件
- 若没有官方文档，再降级到源码、社区文档或项目内经验。
- 该规则应是“条件触发”，不是所有任务都必须先联网查文档。

---

## 约束条件

- 不新增新工作流，只在现有 `dev` / `fix` / `analyze` / `common` 规则内补充护栏。
- 不把“未提交变更提醒”升级为强制阻断，避免与正常的多步连续开发冲突。
- “关键词触发”只能作为意图识别失败时的降级补充，不能成为主判断路径。
- 不要求所有任务都读取外部文档，避免把本地纯实现问题变成无意义的前置调研。
- Commit 简洁化规则只约束主题行，不限制正文、报告、PR 描述的完整度。

---

## 非需求（明确排除）

| 排除项 | 理由 |
|------|------|
| 自动替用户执行 `git commit` | 是否提交仍需用户明确要求，避免误提交 |
| 对所有新消息都强制执行 `git status` 阻断 | 会过度打断正常会话推进 |
| 把所有外部信息源都视为“官方文档” | 社区博客、二手总结不应与官方资料同级 |
| 规定统一的 commit 正文模板 | 当前需求只约束主题简洁性 |

## 验收标准

| # | 标准 | 验证方式 |
|---|------|---------|
| AC-1 | 新需求切换且存在未提交修改时，Agent 会先提示是否先提交当前变更 | 对话场景验证 |
| AC-2 | 同一需求连续迭代时，不会被误判为必须先提交 | 对话场景验证 |
| AC-3 | 用户要求提交时，生成的 commit 主题为一句简洁描述 | 人工审查 |
| AC-4 | 涉及官方 API / 平台能力判断时，Agent 会先读取官方资料再继续分析 | 任务回放验证 |
| AC-5 | 本地纯代码修复任务不会被强制要求先查官方文档 | 对话场景验证 |

## 影响范围

### 预期变更模块

| 模块 | 变更方向 |
|------|---------|
| `instructions/01-common.instructions.md` | 新增跨工作流边界提醒与官方文档优先触发规则 |
| `instructions/10-dev.instructions.md` | 为开发工作流补充任务切换提醒与提交描述要求 |
| `instructions/11-fix.instructions.md` | 为修复工作流补充相同护栏，避免跨问题串改 |
| `instructions/13-analyze.instructions.md` | 强化 research 场景的官方文档优先级 |
| 相关文档（README/requirements/design） | 同步对外说明与需求设计 |

### 潜在影响点

- 会增加部分场景下的前置提醒，用户交互会更保守。
- 会提升外部能力判断的准确性，但在需要查阅官方资料时增加少量前置成本。
- 会让最终 commit message 更短，但要求把详细背景留在报告或回复中。
