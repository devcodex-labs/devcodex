# ⑥ 开发阶段合规检查 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

前置状态汇总完成后，在路由到具体工作流之前，需要一道专门的闸门确认"当前请求是否已经具备进入开发类流程的条件"。  
安全检查解决的是"能不能做"，而开发阶段合规检查解决的是"现在是否准备好进入开发工作流"。

---

## 需求定义

开发阶段合规检查是**路由前的强制闸门**，至少检查以下六项：

| 检查项 | 说明 |
|--------|------|
| 开发类意图是否成立 | chat / 恢复任务 / dev / fix / audit / self-fix / plan 明确区分 |
| profile 与项目上下文是否足够 | 项目/版本/规范边界是否已识别 |
| 产物落点是否明确 | 报告/记忆/需求文档归档路径是否确定 |
| 记忆状态是否冲突 | 是否存在未完成任务，是否应先 resume |
| 执行前约束是否齐备 | 工具/目录/运行条件/权限边界是否满足 |
| 变更边界是否清晰 | 是只读分析、文档调整，还是允许真实开发修改 |

---

## 约束条件

- 检查不通过时**不得进入工作流**，须先补齐缺失上下文或回退到轻路径
- 此节点是路由前最后一道门，检查项不得减少
- ENV_MODE=dev 时仅执行 FC4/FC5 简化检查（合规框架规则）

## 验收标准

- [ ] 六项检查全部执行，不可跳过
- [ ] 任意一项不通过时不进入路由
- [ ] 检查不通过时给出明确的补齐建议
- [ ] 检查通过后输出可供路由节点使用的状态
