# ⑨ 执行阶段合规检查 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

工作流执行完成后，在输出报告之前，需要检查**执行过程本身**是否合规。  
这与完成前合规检查不同：执行阶段检查关注的是"执行链是否完整"，而不是"收尾产物是否存在"。

---

## 需求定义

执行阶段合规检查是**执行完成后、报告输出前**的合规闸门，至少检查以下内容：

| 检查项 | 说明 |
|--------|------|
| 执行步骤完整性 | 是否按对应 workflow 完成了必要执行步骤 |
| 必要扫描/验证 | 是否遗漏必要扫描（fix 三步扫描、api-verification 等）|
| 操作约束遵守 | 是否违反工作流内的操作约束 |
| 异常与失败状态 | 是否存在可恢复失败、未处理异常或中断状态 |

---

## 约束条件

- 检查不通过时**修正后重检**，不得跳过
- FC+SC 累计修正 ≥5 次仍未通过 → 停止循环，输出剩余失败项摘要标 ⚠️
- chat 工作流**豁免**执行阶段合规检查

## 验收标准

- [ ] 工作流执行后自动触发合规检查
- [ ] 检查项覆盖执行步骤完整性、扫描验证、约束遵守、异常状态
- [ ] 不通过时内联修正后重检
- [ ] 修正次数 ≥5 时停止循环并输出警告
- [ ] chat 工作流正确豁免本阶段
