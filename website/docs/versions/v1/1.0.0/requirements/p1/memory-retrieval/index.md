# ④ 检索记忆 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

写入摘要后，Agent 需要根据当前任务意图检索历史上下文。  
不同意图对历史上下文深度的需求不同：`chat` 只需轻量了解，`resume`/`dev`/`fix` 则需深度恢复。  
如果所有意图都做相同深度的读取，要么浪费 token，要么遗漏关键历史状态。

---

## 需求定义

检索记忆是主流程的**第四个必经阶段**，支持分级读取策略：

| 读取策略 | 适用意图 | 内容 |
|---------|---------|------|
| 轻量读 | chat | 仅读取最近几条对话摘要，不加载任务详情 |
| 深度读 | dev / fix / audit / resume | 读取完整任务历史、未完成状态、上次待跟进事项 |

### 记忆检索步骤

1. 按意图确定检索深度
2. 检索并合并与当前任务相关的历史上下文
3. 识别记忆冲突或未完成任务状态（🔄 标记）
4. 输出记忆状态供前置状态汇总节点使用

---

## 约束条件

- 记忆检索**不可直接修改记忆文件**（只读）
- 发现 🔄 未完成任务时，输出提示但不强制阻塞（建议 resume）
- 禁止使用 glob/find 扫描 `.memory/` 隐藏目录，必须使用精确路径读取

## 验收标准

- [ ] 按意图类型选择正确的读取深度
- [ ] 深度读能还原历史任务状态和待跟进事项
- [ ] 发现未完成任务时输出提示
- [ ] 记忆读取为只读，不产生写入操作
