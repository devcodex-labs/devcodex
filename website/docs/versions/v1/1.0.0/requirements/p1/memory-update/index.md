# ⑪ 更新记忆 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

报告输出后，需要将本次会话的执行情况持久化到记忆文件，确保下一个 Agent 或下一次会话能够恢复上下文。  
没有记忆更新，会话之间是孤立的，无法恢复未完成任务，也无法追溯历史决策。

---

## 需求定义

更新记忆是主流程的**第十一个阶段**，包含三层记忆体系：

| 记忆层 | 路径 | 触发时机 |
|--------|------|---------|
| Agent 日记 | `.devcodex/.memory/clients/<agent>/tasks/YYYYMMDD.md` | 每会话必写 |
| Agent SUMMARY | `.devcodex/.memory/clients/<agent>/SUMMARY.md` | 每会话追加索引行 |
| 需求级记忆 | `<任务目录>/.memory/sessions.md` | 有关联需求时写 |
| 全局 SUMMARY | `.devcodex/.memory/SUMMARY.md` | 仅关键决策时写 |

### 记忆文件写入规则

1. 追加/更新 Agent 日记（每会话必写，以 `## 会话 NN` 分段）
2. 更新 Agent SUMMARY（追加本次会话索引行）
3. 按需更新需求级记忆
4. Token 防护检查（>13 轮写编码检查点）

---

## 约束条件

- **禁止询问用户是否需要写入记忆**（S05/C05），强制自动写入
- **禁止覆盖已有内容**（S04/C06），只能追加，使用增量编辑
- **禁止使用终端命令修改 .md 文件**（C09），必须使用编辑器工具
- chat 工作流豁免报告，但**记忆仍须写入**
