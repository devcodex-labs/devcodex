# ⑤ 前置状态汇总 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

记忆检索完成后，在进入开发阶段合规检查之前，需要把前置阶段（预检查/安全检查/摘要/记忆）的所有有效状态信息汇总成一个结构化视图。  
没有这个汇总步骤，开发阶段合规检查需要重复消费零散输入，容易出现状态遗漏和重复判断。

---

## 需求定义

前置状态汇总是主流程的**第五个必经阶段**，负责：

| 步骤 | 说明 |
|------|------|
| 汇总前置状态 | 收集预检查/安全检查/摘要/记忆四个阶段的有效输出 |
| 统一表达 | 将可执行状态与待补齐状态分别标注 |
| 输出状态视图 | 为开发阶段合规检查提供完整的单一输入视图 |

### 状态视图包含内容

1. 意图类型（来自预检查）
2. 安全检查判定结果（通过/操作级违规已处理）
3. 摘要内容（来自写入摘要）
4. 记忆检索状态（含未完成任务提示）
5. 产物落点（来自预检查）
6. 待补齐状态列表（不确定项）

---

## 约束条件

- 前置状态汇总**不产生新的判断**，只做信息聚合
- 所有待补齐项必须在此阶段明确标注，不得遗漏到后续节点
- 输出的状态视图是开发阶段合规检查的唯一输入来源
