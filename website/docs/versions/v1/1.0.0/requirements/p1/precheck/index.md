# ① 预检查 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

Agent 收到用户消息后，不能直接路由到工作流，必须先完成一系列前置准备工作：加载规则基线、识别意图、加载项目上下文（profile）、确定产物落点。  
缺少这个阶段，后续安全检查、记忆检索、路由判断都会缺乏稳定基础，导致错误的上下文假设。

---

## 需求定义

预检查是主流程的**第一个必经阶段**，包含以下固定步骤：

| 步骤 | 说明 |
|------|------|
| 读取规则基线 | 加载核心规则、安全底线（S01~S06）、通用规范（C01~C15）|
| 识别意图 | 通过 `intent` Skill 三问法确定工作流类型（dev/fix/audit/analyze/chat/resume 等）|
| 加载基础 profile | 读取项目 `profile/` 目录下的基础信息 |
| 按意图加载完整 profile | 根据意图类型补充加载工作流专属规范 |
| 确定产物落点 | 确认报告、记忆、需求文档的归档路径 |

---

## 约束条件

- 预检查**不可跳过**，任何工作流都必须先完成预检查
- 规则基线加载失败时，必须按降级路径执行，不得凭 AI 推测规范内容（S03）
- 产物落点必须在此阶段明确，后续节点直接使用，不得重新判断

## 验收标准

- [ ] 每次收到消息后预检查自动触发，不需要用户显式触发
- [ ] 规则基线（S01~S06、C01~C15）加载正确
- [ ] 意图识别结果可供后续节点使用
- [ ] profile 上下文按意图类型正确加载
- [ ] 产物落点（报告路径、记忆路径）在此阶段输出并传递到后续节点
