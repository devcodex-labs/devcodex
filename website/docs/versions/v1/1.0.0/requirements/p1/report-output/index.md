# ⑩ 输出报告 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

执行阶段合规检查通过后，需要将本次工作流的执行结果、问题清单、建议等输出为结构化报告文件。  
报告不能仅在对话中呈现，必须写入文件持久化，方便后续审计、复盘和跨会话引用。

---

## 需求定义

输出报告是主流程的**第十个阶段**，包含以下步骤：

| 步骤 | 说明 |
|------|------|
| 选择报告模板 | 按工作流类型选择对应模板 |
| 确定报告路径 | 需求级优先（`<任务目录>/reports/`），项目级兜底（`reports/<子目录>/`）|
| 填写头部必填项 | 项目/类型/子类型/日期/Agent/状态 |
| 填写正文 | 每条建议附三列验证（合理性/可实施性/收益）|
| 执行报告二次验证 | V1~V6 检查 |
| 输出产物路径 | 回复末尾输出 Markdown 链接 + 纯文本路径双行 |

### 报告路径规则

```
需求级：<任务目录>/reports/<agent>/YYYYMMDD/NN--<简述>.md
项目级：reports/<子目录>/<agent>/YYYYMMDD/NN--<简述>.md
```

| 工作流 | 子目录 |
|--------|--------|
| dev | requirements/ |
| fix | bugs/ |
| analyze | analysis/ |
| audit/self-fix | audit/ |

---

## 约束条件

- **禁止仅在对话中输出报告**，必须写入文件（FC2）
- **禁止覆盖已有报告**，每次会话独立新建文件
- 文件名必须使用 `NN--` 双横杠格式（FC4）
- chat 工作流**豁免**报告输出
