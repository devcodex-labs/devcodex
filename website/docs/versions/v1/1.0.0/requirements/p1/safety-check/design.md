## 方案概述

安全检查通过 `devcodex.agent.md` §② 内联实现，对用户请求逐项执行 S01~S06 判定，分三路分流。

---

## 核心设计

按 `devcodex.agent.md` §② 定义，预检查完成后执行 S01~S06 逐项判定：

- **通过** → 进入 ③ 写入摘要
- **操作级违规**（S01 不可逆 / S04 overwrite / S06 危险命令）→ 阻断该操作，给出合规替代，继续主流程
- **致命违规**（S02 硬编码密钥 / S03 编造规范）→ 写审计记录到记忆 + `data/violations.md`，终止请求

### 违规审计双写机制

AUDIT_LOG 在两个位置触发（相同写入方式）：
1. **② 安全检查（主动）**— 请求本身违反 S02/S03 → 立即终止并创建最小化段落
2. **⑨ 合规检查（被动）**— 执行过程中产出违规内容 → 事后发现并补写审计

## 风险与约束

- S01~S06 全程强制，全自动模式也不可跳过
- 致命违规立即终止，不进入后续节点
- 审计记录必须双写（记忆 + violations.md）
