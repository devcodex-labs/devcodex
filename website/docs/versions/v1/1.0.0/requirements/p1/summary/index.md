# ③ 写入摘要 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

安全检查通过后，需要把"当前这条消息要做什么"压缩成一段稳定的结构化摘要。  
没有摘要，后续的记忆检索将缺乏方向，无法判断该做轻量读还是深度读，也无法区分是否应先恢复上一次未完成的任务。

---

## 需求定义

写入摘要是主流程的**第三个必经阶段**，包含以下步骤：

| 步骤 | 说明 |
|------|------|
| 提取核心信息 | 提取本轮任务目标、约束条件、执行边界 |
| 标准化表达 | 避免冗余与歧义，统一摘要格式 |
| 生成摘要 | 输出可用于后续记忆检索的摘要内容 |
| 质量自检 | 判断摘要是否足够支撑后续检索，不足则补充后重写 |

### 摘要质量标准

1. 覆盖本轮目标、关键约束、执行边界
2. 服务后续"记忆检索"，避免只写表面描述
3. 简洁且可复用，不夹杂执行细节噪音

---

## 约束条件

- 摘要**必须在记忆检索之前**完成，不可顺序颠倒
- 摘要质量不达标时须重写，不得直接进入下一节点
- 摘要内容仅用于本次会话的后续阶段，不写入持久记忆（持久化在 ⑪ 更新记忆）

## 验收标准

- [ ] 安全检查通过后自动进入写入摘要阶段
- [ ] 摘要覆盖目标/约束/边界三项
- [ ] 摘要质量不达标时自动重写，不跳过
- [ ] 摘要输出后传递到记忆检索节点
