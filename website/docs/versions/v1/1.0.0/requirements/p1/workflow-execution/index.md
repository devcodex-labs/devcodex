# ⑧ 工作流执行 — 需求概况

> **优先级**：P1 · **状态**：✅ 已实现

---

## 需求背景

路由完成后，进入各工作流的核心执行阶段。  
不同工作流有完全不同的执行链和约束，需要统一的骨架定义确保每种工作流都被正确执行，不遗漏必要步骤。

---

## 需求定义

工作流执行是主流程的**第八个阶段**，按工作流类型执行不同流程：

| 工作流 | 执行链 |
|--------|--------|
| dev | CP1 → CP2 → plan-review → impact-review（条件）→ CP3 → 执行 → api-verification → document-sync |
| fix | 诊断三步 → CP1 → CP2 → 执行 → 三步扫描 → CP3（条件）|
| audit | 多轮收敛（连续 N 轮无新发现）|
| analyze | 单轮只读分析，输出结论 |
| self-fix | 分级（自动/Pending/拒绝）→ 修复规范文件 |
| plan | 拆解目标 → 执行计划 → 用户确认 → 逐步执行 |
| chat | 直接回复，豁免 CP 和报告 |
| resume | 还原历史上下文 → 继续原工作流 |

---

## 约束条件

- dev/fix 工作流 CP 必须按序执行（C02），不可合并或跳跃
- 编码后必须运行 lint/typecheck/test（SC2）
- error 最多 2 次迭代，仍失败则停止标 ⚠️
- fix 工作流必须执行三步扫描（同类全局/数据联动/grep零残留）

## 验收标准

- [ ] 每种工作流都有独立的执行链定义
- [ ] dev/fix 的 CP 节点不可跳过
- [ ] 编码后自动触发 lint/typecheck/test
- [ ] fix 三步扫描在执行后强制运行
- [ ] 失败 2 次后停止并输出摘要标 ⚠️
